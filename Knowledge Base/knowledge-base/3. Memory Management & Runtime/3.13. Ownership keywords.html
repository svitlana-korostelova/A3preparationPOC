3.13. Ownership keywords

Short answer

Swift 5.9+ lets you say who owns a value. The compiler then needs fewer copies and fewer retain/release calls. Use it only in performance-critical code or for single-owner resources. Normal app code does not need it.

The keywords

  • ~Copyable — the type cannot be copied. There is always one owner.
  • borrowing — the function only reads the value. No copy, no retain.
  • consuming — the function takes the value and uses it up.
  • consume — give up ownership. The old variable cannot be used after it.

Example

struct FileHandle: ~Copyable {
    let fd: Int32
    deinit { close(fd) }                  // runs exactly once
}

func read(_ f: borrowing FileHandle) { }   // only looks
func finish(_ f: consuming FileHandle) { } // takes it

let f = FileHandle(fd: 3)
read(f)
finish(f)    // f is moved here
// read(f)   // ❌ compile error: f was already consumed

Why it matters

  • Fewer copies and ARC calls in hot code (see 3.1).
  • "Use after move" is a compile error, not a runtime crash.

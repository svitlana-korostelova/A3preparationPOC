3.10. When is a value type put on the heap?

Value types (struct, enum, tuples) live on the stack by default. But Swift must move them to the heap in several specific situations. Knowing these cases prevents surprises in profiling and helps write allocaton-free hot paths.

1. Captured by an escaping closure

When a local variable is captured by an @escaping closure, its lifetime must outlive the current stack frame. Swift allocates a capture box — a small heap object — to hold the variable.

func makeCounter() -> () -> Int {
    var count = 0                        // Int (value type)
    return {
        count += 1                       // escaping capture
        return count
    }
    // `count` is boxed on the heap so the returned closure can outlive this frame
}

let next = makeCounter()
next()   // 1
next()   // 2  — `count` is still alive on the heap

2. Stored as a property of a class

A value type stored inside a class lives inside the class's heap allocation. The struct itself doesn't get a separate allocation — it's inline within the object's memory — but it is on the heap because the containing object is.

struct Point { var x, y: Double }

class Circle {
    var center: Point    // Point lives inside Circle's heap block
    var radius: Double
    init(center: Point, radius: Double) {
        self.center = center; self.radius = radius
    }
}

3. Existential container (large value types)

A protocol-typed variable (any Protocol) is stored in an existential container — a 5-word buffer. If the value type fits in 3 words (24 bytes on 64-bit), it lives inline in that buffer (on the stack). If it's larger, Swift allocates a heap buffer and stores a pointer in the container.

protocol Drawable { func draw() }

struct SmallShape: Drawable {        // ≤ 24 bytes — fits inline, no heap
    var x: Double
    func draw() {}
}

struct BigShape: Drawable {          // > 24 bytes — heap allocation
    var a, b, c, d: Double
    func draw() {}
}

let shape: any Drawable = BigShape(a: 1, b: 2, c: 3, d: 4)
// BigShape is heap-allocated inside the existential container

4. Indirect enum

A recursive enum must use indirect to break the infinite size cycle. indirect wraps the associated value in a heap allocation.

indirect enum Tree {
    case leaf(Int)
    case node(Tree, Tree)   // each branch is a heap-allocated box
}

let t: Tree = .node(.leaf(1), .leaf(2))
// t is a pointer to a heap box containing two heap boxes

5. inout in async context

Inside an async function, the compiler cannot guarantee a local variable survives across a suspension point on the original stack frame. Variables referenced via inout (or captured by actors) may be promoted to the heap to maintain correctness across await calls.

func asyncWork() async {
    var buffer = [Int]()       // heap-allocated Array backing store anyway,
                                // but local value variables can also be promoted
    await fetchData()           // suspension point: stack frame may not be valid
    buffer.append(42)          // buffer must survive across the await
}

Compiler optimisation: stack promotion

The compiler can also go the other direction: if it can prove a heap allocation's lifetime is bounded to the current stack frame (escape analysis), it may promote it onto the stack. This is an internal optimisation; you can observe it via the Allocations instrument showing fewer mallocs than expected.

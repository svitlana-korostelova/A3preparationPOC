3.12. Understanding strong, weak, unowned

Strong (default)

Every reference is strong by default. A strong reference increments the object's retain count and keeps it alive as long as the reference exists. When you write let x = MyClass(), x is a strong reference.

class User { var name: String; init(_ n: String) { name = n } }

var a: User? = User("Alice")   // refCount = 1
var b = a                        // refCount = 2
a = nil                          // refCount = 1 — object lives because b holds it
b = nil                          // refCount = 0 → deinit → free

Weak

A weak reference does not increment the retain count. It is always Optional and is automatically set to nil when the object it points to is deallocated. The runtime achieves this via the side table: it writes a pointer back from the object's side table entry to every weak variable, then zeroes them all during dealloc.

class ViewController {
    weak var delegate: (any MyDelegate)?   // does NOT keep delegate alive
}

class Presenter: MyDelegate {}

var vc = ViewController()
var presenter: Presenter? = Presenter()
vc.delegate = presenter            // weak — no retain
presenter = nil                   // Presenter deallocated
print(vc.delegate)                 // nil — automatically zeroed

Unowned

An unowned reference also does not increment the retain count, but it is not Optional. It assumes the referenced object is still alive when accessed. If it has been deallocated and you access an unowned reference, the program traps (EXC_BAD_ACCESS). Use it only when you can guarantee the referenced object outlives the reference holder.

class CreditCard {
    let number: String
    unowned let customer: Customer   // card cannot exist without a customer
    init(number: String, customer: Customer) {
        self.number = number
        self.customer = customer
    }
}
class Customer {
    var card: CreditCard?
}

Closure capture lists

Closures capture variables strongly by default. Use a capture list to break cycles or control lifetime.

class ViewModel {
    var onUpdate: (() -> Void)?

    func setup() {
        // ❌ Retain cycle: closure holds self strongly, self holds closure strongly
        onUpdate = {
            self.refresh()
        }

        // ✅ Weak: safe when ViewModel might be nil by the time closure runs
        onUpdate = { [weak self] in
            self?.refresh()
        }

        // ✅ Unowned: safe only when ViewModel is guaranteed alive during closure
        onUpdate = { [unowned self] in
            self.refresh()
        }
    }

    func refresh() {}
}

Weak + guard let pattern

When you capture self weakly in a closure, use guard let self = self else { return } to create a temporary strong reference for the duration of the closure's execution. This ensures the object isn't deallocated mid-closure while remaining safe if it was already gone when the closure fired.

onUpdate = { [weak self] in
    guard let self else { return }   // promote to strong for this scope
    self.refresh()
    self.updateUI()                   // self cannot be nil here
}

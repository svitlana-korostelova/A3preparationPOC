3.1. Memory management: what is it?

Definition

Memory management is the process of allocating memory for objects when they are needed and freeing that memory when they are no longer needed. On iOS, doing this correctly prevents two failure modes: memory leaks (objects that should be freed are not, wasting RAM) and dangling-pointer crashes (accessing memory after it has been freed — EXC_BAD_ACCESS).

iOS uses ARC, not a garbage collector

Most managed runtimes (JVM, CLR, Go) use a garbage collector: a background process periodically scans the heap, finds unreachable objects, and frees them in a stop-the-world or concurrent pass.

Swift and Objective-C use Automatic Reference Counting (ARC) instead. There is no background GC thread. The compiler inserts retain and release calls at compile time, and an object is freed immediately when its reference count drops to zero.

Stack vs heap — quick overview

iOS processes have two primary memory regions:

  • Stack — per-thread, LIFO, fixed size. Value types (structs, enums, tuples) typically live here. Allocation is a single pointer decrement — essentially free. Automatically reclaimed when the function returns.
  • Heap — shared, dynamic. Class instances always live here. Allocation requires a lock and bookkeeping. Lifetime is managed by ARC.

Before ARC: Manual Reference Counting (MRC)

Before ARC (Xcode 4.2, 2011), Objective-C developers managed memory by hand:

// Objective-C MRC — historical reference only
MyObject *obj = [[MyObject alloc] init];  // refcount = 1
[obj retain];                                  // refcount = 2
[obj release];                                 // refcount = 1
[obj release];                                 // refcount = 0 → dealloc

Forgetting a release → leak. Releasing too early → crash. ARC eliminated this class of bug by having the compiler do it automatically.

What ARC does

ARC is a compile-time transformation. When you write:

func example() {
    let a = MyClass()   // compiler inserts: retain (refcount → 1)
    useIt(a)
}                        // compiler inserts: release (refcount → 0 → deinit)

The compiler inserts the retain/release calls so you never have to. The runtime enforces the counts.

Why it matters for iOS development

  • Memory pressure — iOS kills apps that use too much RAM (jetsam). Leaks grow RSS over time, increasing the risk of an OOM kill.
  • Crashes — accessing a deallocated object causes EXC_BAD_ACCESS, which is hard to reproduce and debug.
  • Performance — excessive ARC traffic (many short-lived objects) adds atomic-operation overhead. Value types avoid this.
  • Retain cycles — two objects holding strong references to each other never reach refcount 0, leaking both permanently.

Swift memory ownership model

Swift 5.9+ formalises ownership with the ~Copyable protocol and consume/borrow keywords, giving developers fine-grained control when needed. For typical app code, ARC is sufficient and ownership annotations are optional.

3.16. Run loop

What is a Run Loop?

A run loop is an event-processing loop tied to a thread. It sleeps when there is nothing to do (no active events) and wakes up to process events as they arrive, then returns to sleep. This "smart sleep" pattern prevents the thread from spinning and burning CPU while idle.

The main thread's run loop is started automatically by UIKit/AppKit on app launch. Background threads do not have a run loop by default — you must start one manually if needed.

What the Run Loop Processes

  • Input sources: port-based (Mach ports, sockets) and custom sources (e.g., perform(_:on:))
  • Timer sources: Timer / CFRunLoopTimer — fire at scheduled times
  • Touch / UI events: delivered by the system via Mach ports to the main run loop
  • CADisplayLink: display-sync callbacks (registered as a timer-like source)
  • Network callbacks: URLSession delegates, CFStream
  • Autorelease pool drain: the main run loop drains the pool at the end of each iteration

Run Loop Modes

A run loop runs in exactly one mode at a time. Sources and timers are registered for specific modes; they only fire when the loop is running in a matching mode.

Mode constantWhen activeWhat fires
.default (NSDefaultRunLoopMode)Normal idle / waitingMost timers, network, perform calls
.tracking (UITrackingRunLoopMode)User is scrolling / draggingOnly tracking-registered sources
.common (NSRunLoopCommonModes)Pseudo-mode — union of tagged modesSources registered here fire in all tagged modes

Classic Bug: Timer Stops During Scroll

// Bug: fires only when not scrolling
let timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { _ in
    updateClock()
}
// scheduledTimer adds to .default mode only
// UIScrollView switches run loop to .tracking → timer is silent during scroll

// Fix: register in .common so it fires in both modes
RunLoop.main.add(timer, forMode: .common)

Run Loop Iteration Pseudocode

// Simplified run loop internals
while true {
    // 1. Notify observers: about to process timers
    notifyObservers(.beforeTimers)

    // 2. Fire any timers whose fire date has passed
    fireExpiredTimers()

    // 3. Notify observers: about to process sources
    notifyObservers(.beforeSources)

    // 4. Process pending source0 (non-port) events
    processPendingSource0Events()

    // 5. If a port (source1) event is ready, handle it immediately
    if hasSource1Events() {
        processSource1Event()
        continue  // restart without sleeping
    }

    // 6. Notify observers: going to sleep
    notifyObservers(.beforeWaiting)

    // 7. Sleep — mach_msg blocks until a port fires or timer expires
    sleepUntilWoken()

    // 8. Woken up — notify observers
    notifyObservers(.afterWaiting)

    // 9. Process the event that woke us, then loop
}

Starting a Run Loop on a Background Thread

class Worker: NSObject {
    func startPersistentThread() {
        let thread = Thread {
            // Must add at least one source before calling run()
            // otherwise the run loop exits immediately (nothing to do)
            RunLoop.current.add(Port(), forMode: .default)
            RunLoop.current.run()  // blocks until no more sources
        }
        thread.start()
    }
}

GCD manages threads internally and you generally never need to start a run loop on a GCD thread. The pattern above is for Thread-based code that needs persistent callbacks (CADisplayLink on a background thread, legacy NSURLConnection, etc.).

Memory Management Relevance

The main run loop's autorelease pool is drained at the end of each iteration. This means objects autoreleased during event handling (UIKit returns many objects autoreleased) are freed before the next frame starts. If you create many autoreleased objects within a single run loop iteration (e.g., a synchronous loop that processes images in a touch handler), they all accumulate until the iteration ends — that is when you need an explicit inner @autoreleasepool.

Run Loop Observers

// Observe run loop activity (e.g. to detect main thread idle)
let observer = CFRunLoopObserverCreateWithHandler(
    nil,
    CFRunLoopActivity.beforeWaiting.rawValue,
    true,   // repeats
    0,      // order
    { observer, activity in
        // Called each time the main thread is about to sleep
        // Good place for: FPS monitoring, deferred work, ANR detection
    }
)
CFRunLoopAddObserver(CFRunLoopGetMain(), observer, .commonModes)

3.13. Swift runtime

What is the Swift runtime?

The Swift runtime is a low-level library — libswiftCore.dylib — embedded into every Swift binary. It sits between your Swift code and the OS, providing services that cannot be resolved at compile time. As of Swift 5.7+, the runtime is stable ABI on Apple platforms, meaning OS versions ship a copy and apps link against it dynamically instead of bundling it.

Object Allocation — swift_allocObject

When you write SomeClass(), the compiler emits a call to swift_allocObject:

  1. Receives the type's metadata pointer and required size/alignment.
  2. Calls malloc (or a custom allocator) to get raw memory.
  3. Writes the isa (metadata pointer) and an initial strong ref count = 1 into the first 16 bytes (the "HeapObject" header).
  4. Returns the pointer; Swift calls the designated init.
// What the compiler emits for:  let obj = MyClass()
// (pseudocode, not real Swift)
let raw = swift_allocObject(
    metadata: &MyClass.metadata,
    requiredSize: MemoryLayout<MyClass>.size,
    requiredAlignment: MemoryLayout<MyClass>.alignment
)
let obj = UnsafeMutablePointer<MyClass>(raw)
MyClass.init(obj)  // calls your init

Type Metadata

Every Swift type has a metadata record in the binary — essentially a struct describing the type at runtime:

  • Kind: class, struct, enum, protocol, etc.
  • Nominal type descriptor: field names, field types, generic parameters.
  • VTable (classes only): array of function pointers for overridable methods.
  • Protocol conformance list: references to witness tables.
  • Field offsets: used by Mirror for reflection.
// Swift type metadata is accessed via reflection
let m = Mirror(reflecting: SomeStruct())
for child in m.children {
    print(child.label ?? "?", child.value)
}
// Internally Mirror reads the nominal type descriptor to enumerate fields

Dynamic Dispatch — VTables vs Witness Tables

VTable dispatch (classes): each class instance's metadata contains a vtable. An overridable method call compiles to load metadata → index into vtable → call function ptr. Sealed with final to let the compiler devirtualize.

Witness table dispatch (protocols): each conformance produces a witness table — a struct of function pointers, one per protocol requirement. Passing a value as a protocol type bundles the value with a pointer to its witness table (the existential container).

protocol Drawable {
    func draw()
}

struct Circle: Drawable {
    func draw() { /* ... */ }
}

// Compiler generates a witness table for Circle : Drawable
// { draw: &Circle.draw }  — one entry per protocol requirement

func render(_ shape: any Drawable) {
    shape.draw()
    // ↑ load witness table ptr from existential → call draw slot
}

Dynamic Casting — swift_dynamicCast

as? and is compile to calls to swift_dynamicCast (and family). For class types it checks the isa chain. For protocol types it queries the runtime conformance cache. For value types inside existentials it compares type metadata pointers.

func classify(_ obj: AnyObject) {
    if let vc = obj as? UIViewController {
        // swift_dynamicCastClass checks the isa hierarchy
        _ = vc
    }
    if let d = obj as? any Equatable {
        // swift_dynamicCast checks the conformance cache
        _ = d
    }
}

Existential Containers

A variable of protocol type (e.g. any Drawable) is stored as an existential container — typically 5 words on the stack:

  • 3 words: inline value buffer (small values fit; large values heap-box and store a pointer here)
  • 1 word: pointer to type metadata
  • 1 word per protocol: pointer to witness table

This layout explains why existential types have a performance cost — every call goes through an indirect witness table lookup, and large values require heap boxing.

@objc Bridging

When a Swift class inherits NSObject or its methods are marked @objc, the Swift compiler registers them with the Obj-C runtime via objc_registerClassPair and method lists. This allows Obj-C code, KVO, KVC, and #selector to work. The cost: every @objc method gets a Obj-C thunk plus an entry in the Obj-C method list.

class MyView: UIView {
    // NSObject subclass → registered with Obj-C runtime automatically

    @objc func handleTap(_ gesture: UITapGestureRecognizer) {
        // Obj-C runtime can call this via objc_msgSend
        // Selector: "handleTap:"
    }
}

// Pure Swift class — NOT registered with Obj-C runtime
final class ViewModel {
    func load() { }  // vtable dispatch only
}

3.7. Heaps and stacks

Swift programs use two memory regions: the stack for deterministic, short-lived data and the heap for dynamic, shared, longer-lived data. Understanding the difference explains why value types are faster and when heap allocations are unavoidable.

Stack

Each thread owns its own stack — a contiguous block of memory managed as a LIFO structure. Allocation is a single decrement of the stack pointer (SP); deallocation is the reverse increment when the function returns. No locks, no searching for free space.

  • Main thread: 8 MB default
  • Background threads: 512 KB default (configurable at thread creation)
  • Exceeding the limit causes a stack overflow → EXC_BAD_ACCESS crash

What lives on the stack: local value types (struct, enum, tuples), function parameters, return values, and saved registers.

Heap

The heap is a single shared region used by all threads. Allocation requires the allocator to find a free block of the right size, update bookkeeping structures, and return a pointer — all while holding a lock (or using lock-free algorithms in modern malloc). Deallocation via ARC inserts a swift_release call; when the strong count reaches zero, free() is called.

What lives on the heap: all class (class) instances, closure capture boxes, large existential containers, indirect enum payloads.

Why it matters for performance

A heap allocation involves a system call or at minimum a spin-lock, plus cache misses when accessing the newly allocated memory. On a hot path (e.g., rendering 60 fps, parsing large JSON), replacing class instances with structs can eliminate thousands of allocations per frame.

// ❌ Class: every Frame is heap-allocated → ARC overhead every frame
class FrameClass {
    var x: Double
    var y: Double
    var width: Double
    var height: Double
    init(x: Double, y: Double, width: Double, height: Double) {
        self.x = x; self.y = y; self.width = width; self.height = height
    }
}

// ✅ Struct: lives entirely on the stack → zero ARC, zero heap allocation
struct FrameStruct {
    var x: Double
    var y: Double
    var width: Double
    var height: Double
}

func render(frames: [FrameStruct]) {
    for f in frames {
        // f is a copy on the stack — no retain/release
    }
}

Quick rule

  • Use struct for independent copies, plain data, hot paths — stack is free.
  • Use class when you need shared identity or managed lifetime — pay the heap cost knowingly.
  • Profile with Instruments → Allocations before optimizing; don't guess.

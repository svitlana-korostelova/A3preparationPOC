3.21. Copy-on-write (COW)

What is COW?

Copy-on-write is an optimisation that makes value-type copies cheap by deferring the actual data duplication until a mutation occurs. Swift's standard library types — Array, Dictionary, Set, String, Data — are value types with COW semantics.

Internally each of these structs holds a reference to a class-backed heap buffer. When you copy the struct, only the reference (8 bytes) is copied, not the buffer. The copy and the original share the same buffer until one of them mutates.

How COW works step by step

OperationBuffer refcountWhat happens
var a = [1, 2, 3]1Buffer allocated, owned by a
var b = a2Only the reference is copied; both share the buffer
b.append(4)1 (new) / 1 (old)refcount > 1 → new buffer allocated, data copied, then 4 appended; a's buffer unchanged
a.append(5)1 (old)refcount = 1 → mutate in place, no copy
var a = [1, 2, 3]
var b = a              // cheap: copies 8-byte pointer, refcount → 2
b.append(4)            // mutation: new buffer, b gets [1,2,3,4], a still [1,2,3]
print(a)               // [1, 2, 3]
print(b)               // [1, 2, 3, 4]

isKnownUniquelyReferenced

The Swift standard library uses isKnownUniquelyReferenced(_:) on the buffer object to decide whether to copy. If the buffer is uniquely owned (refcount = 1), mutate in place. Otherwise, copy first.

// Simplified pseudocode of what Array.append does internally:
mutating func append(_ element: Element) {
    if !isKnownUniquelyReferenced(&buffer) {
        buffer = buffer.copy()   // COW copy
    }
    buffer.insert(element)
}

Implementing COW for a custom type

You can give your own struct the same behaviour by wrapping the data in a class and checking uniqueness before every mutation.

// Step 1: The heap-allocated storage class
final class _Storage {
    var items: [String]
    init(_ items: [String] = []) { self.items = items }
    func copy() -> _Storage { _Storage(items) }
}

// Step 2: The public value type
struct TagList {
    private var storage = _Storage()

    // Ensure unique ownership before any mutation
    private mutating func ensureUnique() {
        if !isKnownUniquelyReferenced(&storage) {
            storage = storage.copy()
        }
    }

    var count: Int { storage.items.count }

    mutating func add(_ tag: String) {
        ensureUnique()
        storage.items.append(tag)
    }
}

var list1 = TagList()
list1.add("swift")
var list2 = list1          // cheap copy of struct (pointer only)
list2.add("ios")           // triggers COW — list2 gets its own storage
// list1.count == 1, list2.count == 2

Performance: passing large arrays is cheap

Because COW defers copying to the moment of mutation, passing a large array to a function that only reads it costs almost nothing — just a pointer copy and a temporary refcount increment.

func analyse(_ data: [Double]) -> Double {
    // No copy of data happens here — only a pointer is passed
    data.reduce(0, +) / Double(data.count)
}

let measurements: [Double] = /* 100 000 items */ []
let avg = analyse(measurements)   // O(1) copy cost at call site

Gotcha: wrapping a COW type in a class breaks COW

If you store an Array inside a class, the class is always uniquely referenced through its own variable — but the array's buffer is owned by that class object. When two class references point to the same object and you mutate the array through one of them, there is no copy — both see the mutation. You've lost value semantics.

class Wrapper {
    var data: [Int] = []
}

let w1 = Wrapper()
let w2 = w1              // w1 and w2 point to the same Wrapper
w2.data.append(42)
// w1.data is also [42] — COW is bypassed because the array is not
// separately owned; both references reach the same Wrapper's storage

Rule: COW works correctly only when the struct holding the buffer is the sole owner (or copies it on mutation). Putting that struct inside a shared class object defeats the uniqueness check.

The _modify accessor

Swift's ownership model includes a _modify coroutine accessor for in-place mutation. When you write array[0] += 1, the compiler uses _modify to yield a mutable reference to the element directly, avoiding an extra copy-in / copy-out cycle that a plain getter + setter would cause. You don't write _modify yourself in normal code, but it is why subscript mutation on COW collections is efficient.

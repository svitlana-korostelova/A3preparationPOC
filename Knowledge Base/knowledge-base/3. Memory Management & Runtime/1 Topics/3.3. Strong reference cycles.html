3.3. Strong reference cycles

What is a retain cycle?

A strong reference cycle (retain cycle) occurs when two or more objects hold strong references to each other, forming a closed loop. Because each object's reference count can never reach zero (they keep each other alive), ARC cannot free them. The result is a memory leak — the objects persist for the lifetime of the process even though no outside code can reach them.

Classic example: two classes

class Person {
    let name: String
    var apartment: Apartment?     // strong reference
    init(_ n: String) { name = n }
    deinit { print("\(name) deallocated") }
}

class Apartment {
    let unit: String
    var tenant: Person?            // strong reference — creates the cycle
    init(_ u: String) { unit = u }
    deinit { print("\(unit) deallocated") }
}

var john: Person?    = Person("John")
var unit4A: Apartment? = Apartment("4A")

john!.apartment = unit4A    // Person → Apartment  (strong)
unit4A!.tenant  = john      // Apartment → Person  (strong)

john   = nil  // Person refcount: 2→1 (Apartment still holds it)
unit4A = nil  // Apartment refcount: 2→1 (Person still holds it)
// deinit never prints — both objects leak

Retain cycle with a delegate

// WRONG — view controller leaks if button holds it strongly
protocol ButtonDelegate: AnyObject {
    func buttonTapped()
}

class MyButton {
    var delegate: (any ButtonDelegate)?   // should be weak
}

class ViewController: ButtonDelegate {
    let button = MyButton()
    init() { button.delegate = self }  // VC → button (strong)
                                          // button → VC (strong) → CYCLE
    func buttonTapped() {}
}

Retain cycle in a closure

class ViewModel {
    var onUpdate: (() -> Void)?

    func setup() {
        onUpdate = {          // closure captures self strongly by default
            print(self.title)  // ViewModel → closure (strong)
        }                     // closure → ViewModel (strong) via self → CYCLE
    }

    var title = "Hello"
    deinit { print("ViewModel gone") }
}

Fix with a capture list: [weak self] or [unowned self].

onUpdate = { [weak self] in
    print(self?.title ?? "")
}

Detection

  • Xcode Memory Graph Debugger (Debug › Memory Graph, or the graph icon in the debug toolbar) — visualises object relationships; leaked objects shown with a purple exclamation badge.
  • Instruments › Leaks — records leak events over time with call stacks.
  • Instruments › Allocations — shows growing live heap even after expected teardown.
  • Unit test — hold a weak reference to the object under test; assert it is nil after releasing the strong reference:
func testNoLeak() {
    weak var leaked: ViewModel?
    autoreleasepool {
        let vm = ViewModel()
        vm.setup()
        leaked = vm
    }
    XCTAssertNil(leaked, "ViewModel should be deallocated")
}

Solutions

ToolWhen to use
weak varBack-reference that is optional (delegate, parent, closure capture of self that may be nil)
unownedBack-reference guaranteed to outlive the holder (e.g. child referring to parent that created it)
Value typeUse struct — no identity, no cycle possible

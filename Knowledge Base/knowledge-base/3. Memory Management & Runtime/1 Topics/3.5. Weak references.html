3.5. Weak references

Definition

A weak reference holds a reference to an object without increasing its retain count. This means it does not keep the object alive. When the object is deallocated, the runtime automatically sets the weak reference to nil.

Syntax rules

  • Must be declared with weak var — never weak let (it must be mutable so the runtime can nil it).
  • Must be Optional — always T?, never T.
  • Only applicable to class instances (AnyObject); structs and enums cannot be held weakly.
class Node {
    weak var parent: Node?    // ✓ weak, optional, var
    var children: [Node] = [] // strong — parent owns children
}

Delegate pattern — the canonical use case

protocol NetworkDelegate: AnyObject {
    func didReceive(data: Data)
}

class NetworkClient {
    weak var delegate: (any NetworkDelegate)?  // weak — avoids cycle

    func fetch() {
        // ... async work ...
        delegate?.didReceive(data: responseData)   // safe — nil if owner gone
    }
}

class ViewController: NetworkDelegate {
    let client = NetworkClient()

    init() {
        client.delegate = self
        // VC → client (strong)   client → VC (weak)  → no cycle
    }

    func didReceive(data: Data) { print("got \(data.count) bytes") }
}

Closure capture list

class ViewModel {
    var name = "Alice"

    func startTimer() {
        Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { [weak self] _ in
            guard let self else { return }  // early exit if ViewModel gone
            print(self.name)
        }
    }
}

Under the hood — the side table

Swift tracks weak references via a side table — a small heap-allocated struct pointed to from the object header. The side table records the object's address and the count of current weak references. When the strong count reaches zero:

  1. deinit runs.
  2. The runtime marks the side table entry as "dead".
  3. Any subsequent load of a weak reference reads the side table, sees "dead", and returns nil.
  4. Once the weak count also reaches zero, the side table itself is freed.

This is sometimes called zeroing weak references. It avoids dangling pointer reads at the cost of one extra indirection per weak-ref load.

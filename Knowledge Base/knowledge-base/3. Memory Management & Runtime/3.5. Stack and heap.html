3.5. Stack and heap

Short answer

The stack is fast, private to one thread, and freed automatically when a function returns. The heap is shared, flexible, slower, and its lifetime is managed by ARC. Local value types (struct, enum, tuples, Int) usually live on the stack. Class instances always live on the heap.

Stack details

A function call moves the stack pointer down by the size of its frame (return address, saved registers, arguments, locals). Returning moves it back up. There is no free(), no ARC and no lock.

Stack overflow happens when frames exceed the stack size, almost always from unbounded recursion. The crash is EXC_BAD_ACCESS on the guard page. On a 512 KB thread you get roughly 1,000–2,500 recursive calls with typical frames. For deep recursion, use an explicit stack in an Array, which lives on the heap:

func dfs(root: TreeNode?) {
    var stack: [TreeNode] = root.map { [$0] } ?? []
    while let node = stack.popLast() {
        // process node
        if let r = node.right { stack.append(r) }
        if let l = node.left  { stack.append(l) }
    }
}

Common real-life bug: a property that calls itself

// ❌ getter calls itself → stack overflow
var name: String {
    get { return name }
}

The compiler usually warns: "Attempting to access 'name' within its own getter". Fix: store the value in a separate property.

// ✅ value lives in _name; name is just a front door
private var _name: String = ""

var name: String {
    get { return _name }
    set { _name = newValue }
}

// ✅ or, to react to changes, use didSet (reads the stored value, no recursion)
var title: String = "" {
    didSet { print("title changed to \(title)") }
}

Heap details

  1. A class init calls swift_allocObject, which calls malloc.
  2. The allocator finds a free block and the runtime writes the 16-byte header (metadata pointer + ref counts).
  3. ARC retains and releases as references are copied.
  4. At count 0: deinit, then free().
class Node {
    var value: Int     // 8 bytes
    var next: Node?   // 8 bytes
}
// Heap size: header 16 + 8 + 8 = 32 bytes minimum

Apple's allocator (libmalloc) uses per-thread caches for small blocks, so contention is low. It cannot move live Swift objects, so many tiny, short-lived allocations can fragment memory.

Why it matters for speed

A heap allocation costs the allocation itself, ARC traffic and cache misses. In a hot path (60 fps rendering, large parsing), replacing small classes with structs can remove thousands of allocations per frame.

Example 1: drawing a chart every frame

// ❌ class: 1,000 heap allocations + ARC on every redraw
final class ChartPointRef {
    var x: CGFloat; var y: CGFloat
    init(x: CGFloat, y: CGFloat) { self.x = x; self.y = y }
}

// ✅ struct: stored inline in one array buffer, no ARC
struct ChartPoint { var x: CGFloat; var y: CGFloat }

override func draw(_ rect: CGRect) {
    let points = prices.enumerated().map { i, price in
        ChartPoint(x: CGFloat(i) * step, y: rect.height - CGFloat(price) * scale)
    }
    // build a UIBezierPath from points…
}

draw(_:) can run 60 times a second. With a class, every point is a separate heap object tracked by ARC. With a struct, all points sit side by side in one array buffer: one allocation, cache-friendly.

Example 2: parsing a large JSON response

struct Transaction: Decodable {
    let id: String       // short strings fit inline; long ones use heap storage
    let amount: Decimal
    let date: Date
}

let items = try JSONDecoder().decode([Transaction].self, from: data)
// struct: 10,000 transactions = 1 array buffer
// class:  10,000 extra heap objects + retain/release on every filter / sort / map

Typical bank-transactions screen: filtering and sorting copy references many times. Classes pay ARC on each copy; structs do not.

Measure with Instruments → Allocations before you optimize.

When a value type ends up on the heap

"Struct = stack" is a default, not a rule. A value is placed on the heap when it must outlive the current stack frame, or when its size is not known or too big.

indirect enum Tree {
    case leaf(Int)

}

The reverse also happens: when escape analysis proves a class instance never leaves its function, the optimizer may allocate it on the stack. Do not rely on it.

Heap objects: buffer (storage) vs box

  • Swift has one heap. Each runtime-managed allocation on it is a heap object: a header (type metadata pointer + reference count) and a payload.
  • Buffer (storage object): a heap object whose payload is a header plus many elements stored one after another.
  • Used by Array, String, Dictionary, Set. The struct holds only a reference to it.
  • Box: a heap object whose payload is one value. The compiler creates it (SIL alloc_box).
  • Used for a var captured by an @escaping closure, an indirect enum payload, and an any Protocol value larger than the 3-word inline value buffer.
  • "Buffer" and "box" are compiler and stdlib terms, not public language API.
  • Both cost a heap allocation and reference counting (ARC).
let ids = [1, 2, 3]   // storage object: many elements

var count = 0
let inc = { count += 1 }  // box: one Int shared with the closure

Quick rule

  • Plain data, hot paths, independent copies → struct.
  • Shared identity or controlled lifetime → class, and accept the heap cost.
  • Profile first. Do not guess.

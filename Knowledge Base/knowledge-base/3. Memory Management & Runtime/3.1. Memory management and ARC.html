3.1. Memory management and ARC

Short answer

Memory management means giving memory to objects when they start and taking it back when they are no longer needed. Swift and Objective-C do this with ARC (Automatic Reference Counting). The compiler adds retain and release calls for you. When an object's strong count reaches 0, it is destroyed immediately. There is no garbage collector.

Two bugs come from doing it wrong: leaks (memory is never freed — see 3.4) and dangling pointers (using freed memory, which gives EXC_BAD_ACCESS).

On iOS the deterministic timing is useful: deinit can close files, cancel requests and remove observers at a known moment.

How ARC works

Every class instance lives on the heap and has a reference count in its header. Structs and enums are not reference counted.

  • retain — count + 1. Happens when a new strong reference is created (assign, pass, capture).
  • release — count − 1. Happens when a reference goes out of scope or is reassigned.
  • Count reaches 0 → deinit runs → memory is freed.
class Dog {
    let name: String
    init(_ name: String) { self.name = name; print("init \(name)") }
    deinit { print("deinit \(name)") }
}

var a: Dog? = Dog("Rex")  // count = 1, prints "init Rex"
var b = a                   // count = 2
a = nil                       // count = 1 (b still holds it)
b = nil                       // count = 0, prints "deinit Rex"

ARC is a compile-time step. The compiler inserts swift_retain / swift_release and removes pairs it can prove are useless. The runtime only does the counting.

Before ARC: manual reference counting (MRC)

Until Xcode 4.2 (2011), Obj-C developers called retain / release by hand. A missing release leaked memory. An extra one crashed the app. ARC removed this whole class of mistakes by generating the calls at compile time.

What the count costs

  • Atomic operations. Retain and release are atomic, so they are thread-safe. Each one adds a memory barrier and cache traffic between cores. A single call takes a few nanoseconds, but millions of them in a hot loop are measurable.
  • 16-byte header on every object (metadata pointer + packed counts). See 3.6.
  • Compiler help: retain/release pairs are merged or removed, final classes allow static dispatch, and short-lived objects may be moved to the stack.

Tip: use struct for plain data. Value types have no reference count. See 3.7.

Why it matters on iOS

  • Memory limit — iOS kills apps that use too much RAM (jetsam). Leaks push the app toward that limit.
  • Crashes — using a freed object is hard to reproduce and debug.
  • Speed — many short-lived objects mean many atomic operations.
  • Retain cycles — ARC cannot free objects that hold each other.

Ownership keywords (Swift 5.9+)

Swift can also express ownership directly: ~Copyable types, plus consume and borrowing / consuming parameters. They remove copies and retains in performance-critical code. Normal app code does not need them.

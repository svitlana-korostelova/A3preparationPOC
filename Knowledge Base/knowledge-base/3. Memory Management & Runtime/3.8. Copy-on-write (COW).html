3.8. Copy-on-write (COW)

Short answer

Copy-on-write makes copying a value type cheap. A copy only duplicates a pointer to the shared storage. The real data is copied later, only when one of the copies is mutated and the storage is shared. Array, Dictionary, Set, String and Data work this way.

How it works

Each of these structs holds a reference to a class-based heap buffer. Before every mutation, it asks: "am I the only owner of this buffer?" The check is isKnownUniquelyReferenced(&buffer), which looks at the strong count.

Consequences:

  • Passing a large array to a function that only reads it is O(1). No data copy.
  • The first mutation of a shared value is O(n). Later ones are cheap.
  • Copy-on-write is checked at runtime, per mutation, so it is not free but is very cheap.

Writing COW for your own type

Keep the data in a final class and call ensureUnique() before every mutating method.

final class Storage {
    var items: [String]
    init(_ items: [String] = []) { self.items = items }
}

struct TagList {
    private var storage = Storage()

    private mutating func ensureUnique() {
        if !isKnownUniquelyReferenced(&storage) {
            storage = Storage(storage.items)   // copy before writing
        }
    }

    var count: Int { storage.items.count }

    mutating func add(_ tag: String) {
        ensureUnique()
        storage.items.append(tag)
    }
}

var l1 = TagList(); l1.add("swift")
var l2 = l1        // shares storage
l2.add("ios")      // l2 copies first. l1.count == 1, l2.count == 2

Rules: keep the storage private, make it a final class, and run the uniqueness check in every mutating method. One missed method breaks value semantics.

Pitfalls

  • Class holding an array. COW protects copies of the struct. If two variables point to the same class instance, they share that instance's array on purpose. No copy happens. This is reference semantics, not a bug.
  • Struct with a class property shares the object between copies. See 3.7.
  • Hidden copy in a loop. Keeping an extra copy of an array while mutating it forces a full copy on the first write.
  • Not all value types are COW. A plain struct with big fixed fields is copied fully every time.
  • _modify accessor. Subscripts on COW collections use it to mutate an element in place without a copy-in/copy-out. You rarely write it yourself.

Interview summary

COW gives value semantics (independent copies) with reference-type performance (shared storage until a write). It relies on one uniqueness check, isKnownUniquelyReferenced, which is built on the reference count from 3.1.

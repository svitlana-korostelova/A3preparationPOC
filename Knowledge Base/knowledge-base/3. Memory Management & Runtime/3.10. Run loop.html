3.10. Run loop

Short answer

A run loop is an event loop that belongs to one thread. It sleeps when there is nothing to do, wakes up when an event arrives (touch, timer, network, port message), handles it, then sleeps again. UIKit starts the main thread's run loop at launch. Background threads have none until you run one.

What it handles

  • Input sources: port-based (Mach ports, sockets) and custom sources (perform(_:on:)).
  • Timers: Timer (CFRunLoopTimer).
  • UI events: touches arrive through a Mach port.
  • Display link: CADisplayLink frame callbacks.
  • Observers: callbacks at points like "before waiting". Used by the autorelease pool and by monitoring tools.

Modes

A run loop runs in one mode at a time. A timer or source only fires when the loop is in a mode it was added to.

ModeWhenNotes
.defaultNormal idle stateWhere Timer.scheduledTimer adds the timer
.tracking (UITrackingRunLoopMode)While the user scrolls or dragsDefault-mode timers pause
.commonPseudo-mode: a set of modes (default + tracking)A source added here fires in all of them

Classic bug: timer stops while scrolling

let timer = Timer(timeInterval: 1, repeats: true) { _ in updateClock() }

// scheduledTimer would use .default only: silent during scroll
RunLoop.main.add(timer, forMode: .common)   // fires while scrolling too

One loop iteration (simplified)

  1. Notify observers: about to handle timers, then sources.
  2. Fire timers that are due. Run pending non-port sources.
  3. If a port event is ready, handle it and go back to the start.
  4. Notify observers: about to sleep. (The main run loop drains the autorelease pool around here.)
  5. Sleep until a port message or timer wakes the thread.
  6. Notify observers: woke up. Handle the event. Repeat.

Link to memory

The main run loop wraps each iteration in an autorelease pool (see 3.9). Objects autoreleased while handling one event live until that iteration ends. If one event handler runs a long synchronous loop that creates many Obj-C objects, memory grows until the handler returns. Add an inner autoreleasepool.

Running a loop on a background thread

Needed only for Thread-based code that wants timers or callbacks on that thread. A loop with no sources or timers exits immediately, so add one first. With GCD you normally never do this.

let thread = Thread {
    RunLoop.current.add(Port(), forMode: .default)   // keep the loop alive
    RunLoop.current.run()                          // blocks, handling events
}
thread.start()

Observing the loop

An observer on "before waiting" tells you the main thread finished its work. Useful for frame-rate monitoring and hang detection.

let observer = CFRunLoopObserverCreateWithHandler(
    nil, CFRunLoopActivity.beforeWaiting.rawValue, true, 0
) { _, _ in
    // the main thread is about to sleep
}
CFRunLoopAddObserver(CFRunLoopGetMain(), observer, .commonModes)

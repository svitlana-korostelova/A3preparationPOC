1.8. How do structs and classes differ in memory layout (stack vs heap)?

Stack vs Heap

The stack is a fixed-size, LIFO region per thread. Allocation is a single stack-pointer decrement — essentially free. Memory is reclaimed automatically when the function returns.

The heap is a shared, dynamically managed region. Allocation requires locking and bookkeeping. Lifetime is controlled by ARC (atomic retain/release on every copy).

Structs — Stack (usually)

Value types are stored inline: a local struct lives entirely on the stack. No reference counting, no heap allocation for the struct itself.

struct Point {
    var x: Double  // 8 bytes
    var y: Double  // 8 bytes
}

func compute() {
    let p = Point(x: 1, y: 2)  // 16 bytes on the stack frame
    // p is gone when compute() returns — no ARC involved
}

Value Types with Heap-Allocated Storage

A struct that contains a heap-backed type (String, Array, Data, Text, or any class instance) still performs ARC on those stored references. The struct header sits on the stack; the data it owns lives on the heap.

struct Profile {
    var name:   String  // String buffer is heap-allocated
    var scores: [Int]    // Array storage is heap-allocated
    var avatar: Data    // Data byte buffer is heap-allocated
    var label:  Text    // SwiftUI.Text internals are heap-allocated
}

Copying Profile is cheap (the struct header is small), but each heap-owning field triggers a retain on copy.

Classes — Heap (always)

Reference types are heap-allocated. A local variable holds an 8-byte pointer on the stack; the actual object and its ARC metadata live on the heap. Every assignment copies the pointer, not the data.

class Node {
    var value: Int
    var next: Node?
    init(_ v: Int) { value = v }
}

func build() {
    let n = Node(42)
    // stack: 8-byte pointer `n`
    // heap:  Node data + ARC header (~32+ bytes)
} // ARC releases Node here when ref count hits 0

4-Point Structural Comparison

StructClass
Inheritance None — protocol conformance only Single-class inheritance + protocol conformance
Dispatch Static — call site resolved at compile time; can be inlined Dynamic — vtable lookup at runtime; final lets compiler devirtualize
Memory Inline on the stack (or inline in enclosing type) Always heap; variable is an 8-byte pointer
Reference counting No ARC on the struct itself (only on heap-owning fields) ARC on every copy — atomic retain/release

Dispatch example

struct Circle {
    var radius: Double
    func area() -> Double { .pi * radius * radius }
    // ↑ static dispatch — compiler resolves this call directly
}

class Shape {
    func area() -> Double { 0 }
    // ↑ dynamic dispatch — runtime consults vtable
}

class Square: Shape {
    override func area() -> Double { side * side }
    // ↑ still dynamic — replaces Shape's vtable entry
}

final class Triangle {
    func area() -> Double { base * height / 2 }
    // ↑ compiler can devirtualize: final + no override possible
}

When the Compiler Promotes Structs to the Heap

A local value type is promoted to the heap when its lifetime must outlive its stack frame — typically when captured by an escaping closure.

func makeCounter() -> () -> Int {
    var count = 0
    return { count += 1; return count }
    // ↑ escaping capture — `count` box is heap-allocated
}

Quick Rule

  • Prefer struct for plain data, independent copies, hot paths — no ARC overhead, no vtable.
  • Use class when you need shared identity, inheritance, or lifecycle management (e.g., a view controller, a network session).

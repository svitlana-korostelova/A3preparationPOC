1.9. What is the connection between static and atomic?

Short answer

There is no direct link. They are about different things, but a few places connect them.

What each one means

Meaning
staticIn Swift: belongs to the type, not to an instance (static let shared). In "static dispatch": the compiler picks the method at compile time.
atomicOne indivisible step that other threads cannot interrupt. It is a thread-safety idea.

Where they meet

  1. Static dispatch cuts atomic work. Retain and release are atomic operations. With final classes or structs, the compiler knows exactly what runs. It can merge or remove retain/release pairs, so fewer atomic operations are needed. See 3.1.
  2. static let initialization is thread-safe. Swift initializes a static or global property lazily, once, with an atomic mechanism (swift_once, like dispatch_once). Two threads cannot both run the initializer. This protects only the first creation.
  3. static var is not atomic. Reading and writing it from many threads is still a data race. Use a lock, a serial queue or an actor.
  4. Obj-C atomic properties. atomic is the default. It makes the getter and setter whole, so you never read a half-written value. It does not make your code thread-safe: count += 1 is still a race. Swift has no atomic keyword.
class Config {
    static let shared = Config()  // created once, thread-safe
    static var counter = 0          // NOT thread-safe to mutate
}

// Data race: many threads run counter += 1 at the same time
DispatchQueue.concurrentPerform(iterations: 1000) { _ in
    Config.counter += 1
}

Interview answer

"static is about where something lives and when it is resolved. atomic is about thread safety. Static dispatch reduces atomic retain/release cost. static let is initialized once in a thread-safe way, but static var is not safe to mutate from many threads."

2.1.6.4. Ways to build UIKit UI and pass data across storyboards

What are the ways to build UI in UIKit? How do you navigate between storyboards without code, and how do you pass data before the transition?

Say this: Three ways to build the UI: code, a XIB, or a storyboard. The arrow between storyboard scenes is a segue. A storyboard reference is how that arrow jumps to a scene in another storyboard, still without code. Data is passed in prepare(for:sender:) before the destination appears. When I need a real initializer, I leave the segue and use instantiateViewController(identifier:creator:).

The storyboard / XIB / NIB comparison table is already in 2.2.3.3.2. This page only adds the navigation and the data hand-off.

  • Code. You create the views and the push or present yourself. Dependencies go in init. This is the testable path.
  • XIB. One view, one cell, or one controller. You load it with UINib or by name. Navigation stays in code.
  • Storyboard. Many scenes. The relationship and the segue are stored in the file.

Navigate without code. Draw a segue (show, show detail, present, or a relationship). To land in a different storyboard, drop a storyboard reference on the canvas and point the segue at it. UIKit instantiates the destination. You do not call pushViewController.

Pass data before the transition. prepare(for:sender:) runs on the source after the destination exists and before it appears. Cast segue.destination and set properties. sender is whatever you passed to performSegue, often the tapped model.

override func prepare(for segue: UIStoryboardSegue, sender: Any?) {
    guard let details = segue.destination as? AccountDetailsViewController,
          let id = sender as? Account.ID else { return }
    details.accountID = id
}

When the destination needs an initializer. A storyboard always calls init(coder:), so a custom init is not used by a segue. instantiateViewController(identifier:creator:) (iOS 13) is the code path that still loads the layout from the storyboard and lets you inject:

let details = storyboard.instantiateViewController(identifier: "AccountDetails") { coder in
    AccountDetailsViewController(coder: coder, accountID: id)
}
navigationController.pushViewController(details, animated: true)

That second path is code. I use it when the screen has dependencies. I use prepare(for:) when the screen is already a segue and the only input is a property.

If you stall: "What is the arrow between screens called?" A segue.

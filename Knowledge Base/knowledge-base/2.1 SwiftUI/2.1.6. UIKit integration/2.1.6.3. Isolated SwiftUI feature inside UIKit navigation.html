2.1.6.3. Isolated SwiftUI feature inside UIKit navigation

The app is UIKit with a UINavigationController. A new feature is six SwiftUI screens, opened from one UIKit screen. How do you organise navigation inside the feature, and why?

Say this: One owner of the stack. I push a UIHostingController per screen from a coordinator that drives the existing navigation controller. I do not put a second NavigationStack inside the host unless I am ready to name what breaks.

Why this fits a UIKit app:

  • The system back button, the interactive pop, and deep links stay on the navigation controller the rest of the app already uses.
  • Each screen is still SwiftUI. The host is the bridge. Hide SwiftUI's own bar so you do not get two bars. That double-bar case is already written in 2.1.10.4.
  • The view model emits a route. The coordinator creates the next host and pushes it. The view model does not import UIKit. Ownership and the route stream are in 10.26.
func showDetails(_ id: Account.ID) {
    let view = AccountDetailsView(viewModel: detailsModel(id))
        .toolbar(.hidden, for: .navigationBar)
    let host = UIHostingController(rootView: view)
    navigationController.pushViewController(host, animated: true)
}

The other design, and the trade-offs. One UIHostingController whose root view is a NavigationStack of all six screens. Acceptable when the feature must not touch the legacy stack. Say these costs out loud:

  • Back gesture and the back button belong to SwiftUI. The outer navigation controller only sees one screen, so a deep link into screen 4 has to be turned into a NavigationPath the UIKit stack does not know about.
  • UIKit appearance (large titles, the existing bar) stops at the host.
  • A unit test has to read SwiftUI path state, unless you still inject a router. The coordinator-plus-spy test is easier. The spy itself is Q7 on the MVVM page.

If you stall: "Who owns the navigation stack?" Then: "How would you test this navigation?"

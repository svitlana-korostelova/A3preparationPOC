**5.4. How do you handle navigation state restoration?**

  • Conceptual Understanding

    1. Why does NavigationPath not expose its contents directly, and how does that impact your state restoration strategy?

      NavigationPath is opaque by design

    2. What is the difference between @SceneStorage and UserDefaults for persisting navigation state, and when would you choose one over the other?

    Feature @SceneStorage  UserDefaults 
    Ease of Use Very easy, less code More manual, more code
    Scope Per scene App-wide
    Data Type Codable, simple types Codable, any type
    Cross-device Sync No No (unless using iCloud)
    Flexibility Limited High
    1. Why must navigation destination types conform to both Hashable and Codable, and what breaks if they don't?
    - Navigation destination types must conform to Hashable so SwiftUI can uniquely identify and manage them in the navigation stack, and to Codable so their state can be saved and restored for navigation state restoration.
    1. What are the tradeoffs between using NavigationPath vs a typed array [AppDestination] as your navigation state?

    ```swift import SwiftUI

    struct ContentView: View { // SceneStorage automatically persists this value per scene @SceneStorage("navPath") private var navPathData: Data? @State private var navPath: [String] = []

    var body: some View {
    NavigationStack(path: $navPath) {
        List {
            NavigationLink("Go to Detail A", value: "A")
            NavigationLink("Go to Detail B", value: "B")
        }
        .navigationDestination(for: String.self) { value in
            Text("Detail \(value)")
        }
    }
    .onChange(of: navPath) { newValue in
        // Encode and save path when it changes
        navPathData = try? JSONEncoder().encode(newValue)
    }
    .onAppear {
        // Restore path on appear
        if let data = navPathData,
           let savedPath = try? JSONDecoder().decode([String].self, from: data) {
            navPath = savedPath
        }
    }
}

    } ```

    Key Takeaways

    • NavigationPath is opaque — encode/decode only as a whole, can't inspect contents
    • @SceneStorage is preferred over UserDefaults — handles iPad multi-window automatically
    • Typed array [AppDestination] is simpler than NavigationPath if all destinations are the same type
    • Always version-check restored state — app updates can make old paths invalid
    • Centralize navigation in a Router for large apps — easier to save/restore one object
    • path.codable returns nil if path contains non-Codable types — always guard against it

**2.1. SwiftUI data flow. What is the "single source of truth" concept?**

  • Data Flow: property wrappers (@State, @Binding, @ObservedObject, @EnvironmentObject) manage data flow.
  • Single Source of Truth: one reason to change; all views reference this, preventing data inconsistency.

Single Source of Truth in SwiftUI

The “single source of truth” means that each piece of data in your app is stored and managed in only one place. All parts of your UI that need to read or modify that data refer to this single, authoritative source, rather than keeping their own separate copies.

How is it implemented in SwiftUI?

  • The owner of the data (often a parent view or a model object) holds the state.
  • Child views receive access to this state via bindings or environment objects, not by duplicating the data.
  • For app-wide state, you can use an ObservableObject injected with @EnvironmentObject so all views reference the same instance.

Example:

struct ParentView: View {
    @State private var counter = 0 // Single source of truth

    var body: some View {
        ChildView(counter: $counter)
    }
}

struct ChildView: View {
    @Binding var counter: Int

    var body: some View {
        Button("Increment") {
            counter += 1
        }
    }
}

Here, counter is owned by ParentView and accessed by ChildView via a binding. There’s only one place where the value lives and changes.

Summary:

The single source of truth principle ensures that each piece of data is managed in one place, making your app’s state consistent, predictable, and easier to maintain. All views reference this source, so updates are always reflected everywhere in the UI.

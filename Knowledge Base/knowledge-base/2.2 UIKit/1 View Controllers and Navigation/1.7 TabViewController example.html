1.7. TabViewController example

UITabBarController is a container VC (see 1.6) that manages an array of viewControllers, shows one at a time, and lets the user switch via the tab bar. Each tab is usually a UINavigationController wrapping the actual screen, so pushing works independently per tab.

final class MainTabBarController: UITabBarController {

    override func viewDidLoad() {
        super.viewDidLoad()

        let home = UINavigationController(rootViewController: HomeViewController())
        home.tabBarItem = UITabBarItem(title: "Home", image: UIImage(systemName: "house"), tag: 0)

        let search = UINavigationController(rootViewController: SearchViewController())
        search.tabBarItem = UITabBarItem(title: "Search", image: UIImage(systemName: "magnifyingglass"), tag: 1)

        let profile = UINavigationController(rootViewController: ProfileViewController())
        profile.tabBarItem = UITabBarItem(title: "Profile", image: UIImage(systemName: "person"), tag: 2)

        viewControllers = [home, search, profile]   // order = tab order
        selectedIndex = 0
        delegate = self   // see explanation below
    }
}

What delegate = self means: UITabBarController has a weak var delegate: UITabBarControllerDelegate? property — the standard delegation pattern used throughout UIKit. By writing delegate = self, MainTabBarController registers itself as the object that should be notified about tab bar events (e.g. "user is about to select this tab", "user did select this tab"). It's exactly the same pattern as tableView.delegate = self or scrollView.delegate = self.

  • self must conform to UITabBarControllerDelegate (done via the extension MainTabBarController: UITabBarControllerDelegate below) — otherwise it's a compile error.
  • The property is weak to avoid a retain cycle (the tab bar controller doesn't own its delegate).
  • Without setting delegate, UITabBarController works fine for basic tab switching — the delegate is only needed if you want to hook into the switching process: veto a switch (shouldSelect), react after a switch (didSelect), or customize animated transitions between tabs (animationControllerForTransitionFrom:to:).

Common tasks:

// switch tab programmatically
tabBarController?.selectedIndex = 1

// badge on a tab
tabBarController?.viewControllers?[1].tabBarItem.badgeValue = "3"

// intercept/veto a tab switch
extension MainTabBarController: UITabBarControllerDelegate {
    func tabBarController(_ tabBarController: UITabBarController,
                           shouldSelect viewController: UIViewController) -> Bool {
        // e.g. block leaving an unsaved form, or require login for a tab
        return true
    }
}

Each tab's UINavigationController is set as the root by UITabBarController, which is why viewWillAppear/viewDidDisappear fire correctly on the visible tab's top VC — same containment mechanism as 1.6.

Common Interview Questions

Q: Why wrap each tab's root VC in its own UINavigationController? A: So each tab keeps its own independent push/pop navigation stack — switching tabs and back preserves where you were in each stack.

Q: How do you badge a tab or add a "More" overflow? A: tabBarItem.badgeValue for badges; if you have more than 5 tabs, UITabBarController automatically adds a "More" tab that lists the rest.

Q: How would you build this in SwiftUI instead? A: TabView { ... .tabItem { ... } } — conceptually the same container pattern, just declarative.

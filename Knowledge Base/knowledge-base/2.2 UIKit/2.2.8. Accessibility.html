2.2.8. Accessibility

Accessibility (a11y) means everyone can use the app: blind or low-vision users, users with motor limits, deaf users, and users who just prefer large text. UIKit gives most of it through standard controls. Your job is to give correct information to custom views and not break the system settings.

System features to support

FeatureWhat it doesWhat you do
VoiceOverScreen reader. Reads label, value, traits, hint.Set accessibility properties, control reading order.
Dynamic TypeUser-chosen text size (up to AX5).Use text styles, adjustsFontForContentSizeCategory, flexible layout.
Voice Control / Switch ControlControl the app by voice or with a switch.Good labels, real controls, reachable actions.
Reduce Motion / Prefer Cross-FadeLess movement.Check UIAccessibility.isReduceMotionEnabled; swap parallax or zoom for fade.
Increase Contrast, Bold Text, Reduce Transparency, Differentiate Without ColorVisual help.Use semantic system colours; never use colour as the only signal.

Key API (UIAccessibility)

  • isAccessibilityElement: true makes a view reachable. Standard controls are already true; plain UIView and container views are false.
  • accessibilityLabel: short name of the thing, "Play". No role word ("button"), no punctuation games.
  • accessibilityValue: current state, "50 percent", "On".
  • accessibilityHint: result of the action, only when it is not obvious: "Opens the settings".
  • accessibilityTraits: role and state: .button, .header, .selected, .adjustable, .notEnabled.
  • accessibilityIdentifier: not read by VoiceOver. Only for UI tests.
  • accessibilityElements: set the order and group of children in a container. accessibilityCustomActions: extra actions in the VoiceOver rotor. accessibilityViewIsModal: hide everything behind a custom popup.

Example: table cell

final class ProductCell: UITableViewCell {
    let titleLabel = UILabel()
    let priceLabel = UILabel()
    let iconView = UIImageView()
    var onFavorite: (() -> Void)?

    func configure(title: String, price: String) {
        titleLabel.text = title
        priceLabel.text = price
        titleLabel.font = .preferredFont(forTextStyle: .headline)
        titleLabel.adjustsFontForContentSizeCategory = true
        titleLabel.numberOfLines = 0 // grow with big text

        iconView.isAccessibilityElement = false // decorative

        isAccessibilityElement = true // one swipe for the whole cell, not three
        accessibilityLabel = "\(title), \(price)"
        accessibilityTraits = .button
        accessibilityCustomActions = [
            UIAccessibilityCustomAction(name: "Add to favorites") { [weak self] _ in
                self?.onFavorite?()
                return true
            }
        ]
    }
}

Dynamic Type

// System font: automatic
label.font = .preferredFont(forTextStyle: .body)
label.adjustsFontForContentSizeCategory = true

// Custom font: scale it
let base = UIFont(name: "Avenir-Medium", size: 16)!
label.font = UIFontMetrics(forTextStyle: .body).scaledFont(for: base)

// Switch to vertical layout when text is very large
registerForTraitChanges([UITraitPreferredContentSizeCategory.self]) { (self: Self, _) in
    self.stackView.axis = self.traitCollection.preferredContentSizeCategory.isAccessibilityCategory
        ? .vertical : .horizontal
}

Announce changes

UIAccessibility.post(notification: .announcement, argument: "Upload finished")  // spoken message
UIAccessibility.post(notification: .layoutChanged, argument: errorLabel)        // part of screen changed, move focus
UIAccessibility.post(notification: .screenChanged, argument: nil)               // new screen shown

Tools

  • Accessibility Inspector (Xcode → Open Developer Tool): inspect labels and traits, run an audit, change text size on Simulator.
  • VoiceOver on a real device: the only real test. Use Accessibility Shortcut (triple-click the side button).
  • Automated audit in UI tests: try app.performAccessibilityAudit() (Xcode 15+) finds missing labels, small hit areas, clipped text, low contrast.
  • Environment Overrides in the Xcode debug bar: text size, contrast, bold text.

Checklist

  • Every interactive element has a label and the right trait.
  • Touch target at least 44×44 pt.
  • Reading order follows the visual order. Group related items (cell, card).
  • Text scales; nothing is cut at the largest size.
  • Information is not given by colour alone. Contrast is at least 4.5:1 for normal text.
  • Animations respect Reduce Motion.

Follow-up questions

  • Label vs hint vs identifier? Label is what it is, hint is what happens, identifier is for tests and is silent.
  • How do you make a custom-drawn view accessible? Set isAccessibilityElement = true with label, value, and traits. If it has several parts (a chart), set accessibilityElements to a list of UIAccessibilityElement objects, each with its own accessibilityFrameInContainerSpace.
  • How do you build a custom slider or stepper? Add the .adjustable trait and implement accessibilityIncrement() and accessibilityDecrement(). Update accessibilityValue.
  • A custom popup is open, but VoiceOver reads the screen behind it. Why? Set accessibilityViewIsModal = true on the popup, and post .screenChanged or .layoutChanged with the popup as argument.
  • How do you hide something from VoiceOver? For one decorative view, set isAccessibilityElement = false. For a whole subtree, set accessibilityElementsHidden = true on the container.
  • How do you react when the user changes text size while the screen is open? Labels with adjustsFontForContentSizeCategory update by themselves. For layout changes, observe the trait UITraitPreferredContentSizeCategory (iOS 17+) or traitCollectionDidChange (older).

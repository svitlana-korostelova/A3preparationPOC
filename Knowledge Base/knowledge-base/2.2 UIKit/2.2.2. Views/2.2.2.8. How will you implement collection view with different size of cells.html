2.2.2.8. How will you implement collection view with different size of cells ?

  • Three practical approaches, in order of preference today: UICollectionViewCompositionalLayout (iOS 13+, declarative, supports mixed sizes/orientations/nested groups), UICollectionViewFlowLayout with self-sizing or a delegate callback (works everywhere, imperative), and a custom UICollectionViewLayout subclass (full control — Pinterest/waterfall-style grids, custom geometry).

1. Compositional layout (preferred, modern)

  • Build layout from NSCollectionLayoutSize → NSCollectionLayoutItem → NSCollectionLayoutGroup → NSCollectionLayoutSection. Sizes are expressed as .fractionalWidth/.fractionalHeight/.absolute/.estimated, so different cells in the same section can have different dimensions without any delegate math.
  • .estimated(_:) lets Auto Layout compute the final size per cell (self-sizing), which is the standard way to mix cells whose content (e.g. text length, image aspect ratio) drives height.
  • Can combine with UICollectionViewDiffableDataSource and per-section layouts (UICollectionViewCompositionalLayout(sectionProvider:)) for very different card sizes across sections in one view.
func makeLayout() -> UICollectionViewCompositionalLayout {
    let smallItem = NSCollectionLayoutItem(
        layoutSize: NSCollectionLayoutSize(widthDimension: .fractionalWidth(1.0),
                                              heightDimension: .fractionalHeight(1.0)))
    smallItem.contentInsets = NSDirectionalEdgeInsets(top: 4, leading: 4, bottom: 4, trailing: 4)

    // two stacked small items next to one large item
    let pairGroup = NSCollectionLayoutGroup.vertical(
        layoutSize: NSCollectionLayoutSize(widthDimension: .fractionalWidth(0.3),
                                              heightDimension: .fractionalHeight(1.0)),
        subitems: [smallItem, smallItem])

    let bigItem = NSCollectionLayoutItem(
        layoutSize: NSCollectionLayoutSize(widthDimension: .fractionalWidth(0.7),
                                              heightDimension: .fractionalHeight(1.0)))

    let rowGroup = NSCollectionLayoutGroup.horizontal(
        layoutSize: NSCollectionLayoutSize(widthDimension: .fractionalWidth(1.0),
                                              heightDimension: .absolute(200)),
        subitems: [bigItem, pairGroup])

    let section = NSCollectionLayoutSection(group: rowGroup)
    return UICollectionViewCompositionalLayout(section: section)
}

Wiring makeLayout() into a view controller

  • Pass the layout to UICollectionView(frame:collectionViewLayout:) (or set collectionView.collectionViewLayout later); register the cell class; hand the collection view to a UICollectionViewDiffableDataSource; apply a snapshot to populate it.
struct GalleryItem: Hashable {
    let title: String
    let isFeatured: Bool
}

final class GalleryCell: UICollectionViewCell {
    static let reuseID = "GalleryCell"
    private let label = UILabel()

    override init(frame: CGRect) {
        super.init(frame: frame)
        contentView.backgroundColor = .secondarySystemBackground
        label.translatesAutoresizingMaskIntoConstraints = false
        contentView.addSubview(label)
        NSLayoutConstraint.activate([
            label.centerXAnchor.constraint(equalTo: contentView.centerXAnchor),
            label.centerYAnchor.constraint(equalTo: contentView.centerYAnchor)
        ])
    }

    required init?(coder: NSCoder) { fatalError("init(coder:) has not been implemented") }

    func configure(with item: GalleryItem) {
        label.text = item.title
    }
}

final class GalleryViewController: UIViewController {
    private enum Section { case main }

    private var collectionView: UICollectionView!
    private var dataSource: UICollectionViewDiffableDataSource<Section, GalleryItem>!
    private let items: [GalleryItem] = [
        GalleryItem(title: "Featured", isFeatured: true),
        GalleryItem(title: "A", isFeatured: false),
        GalleryItem(title: "B", isFeatured: false)
    ]

    override func viewDidLoad() {
        super.viewDidLoad()

        // 1. Create the collection view with the layout built above.
        collectionView = UICollectionView(frame: view.bounds, collectionViewLayout: makeLayout())
        collectionView.autoresizingMask = [.flexibleWidth, .flexibleHeight]
        collectionView.register(GalleryCell.self, forCellWithReuseIdentifier: GalleryCell.reuseID)
        view.addSubview(collectionView)

        // 2. Connect a diffable data source that dequeues and configures cells.
        dataSource = UICollectionViewDiffableDataSource<Section, GalleryItem>(
            collectionView: collectionView
        ) { collectionView, indexPath, item in
            let cell = collectionView.dequeueReusableCell(
                withReuseIdentifier: GalleryCell.reuseID, for: indexPath
            ) as! GalleryCell
            cell.configure(with: item)
            return cell
        }

        // 3. Push the initial data through a snapshot to populate the grid.
        var snapshot = NSDiffableDataSourceSnapshot<Section, GalleryItem>()
        snapshot.appendSections([.main])
        snapshot.appendItems(items)
        dataSource.apply(snapshot, animatingDifferences: false)
    }
}

2. Flow layout (legacy but still valid)

  • Delegate-driven: implement collectionView(_:layout:sizeForItemAt:) in UICollectionViewDelegateFlowLayout and return a per-item CGSize computed from your model (e.g. text length, aspect ratio table).
  • Self-sizing alternative: set flowLayout.estimatedItemSize = .automatic (or a rough estimate) and let Auto Layout constraints inside the cell determine the final size — avoids a switch/lookup in the delegate but requires the cell's content view to be fully constrained top-to-bottom.
func collectionView(_ collectionView: UICollectionView, layout: UICollectionViewLayout,
                    sizeForItemAt indexPath: IndexPath) -> CGSize {
    let item = items[indexPath.item]
    let width = item.isFeatured ? collectionView.bounds.width : collectionView.bounds.width / 2
    return CGSize(width: width, height: item.isFeatured ? 240 : 140)
}

3. Custom UICollectionViewLayout (waterfall/Pinterest grids)

  • Override prepare() to compute and cache an [UICollectionViewLayoutAttributes] per index path (tracking a running height per column), override collectionViewContentSize, and layoutAttributesForElements(in:)/layoutAttributesForItem(at:) to return the cached frames.
  • Needed when item placement isn't expressible as rows/columns of fixed proportions — e.g. masonry layouts where the next item's column is chosen by "shortest column so far".
protocol PinterestLayoutDelegate: AnyObject {
    func collectionView(_ collectionView: UICollectionView, heightForItemAt indexPath: IndexPath, width: CGFloat) -> CGFloat
}

final class PinterestLayout: UICollectionViewLayout {
    weak var delegate: PinterestLayoutDelegate?
    var numberOfColumns = 2
    var cellPadding: CGFloat = 6

    private var cache: [UICollectionViewLayoutAttributes] = []
    private var contentHeight: CGFloat = 0
    private var contentWidth: CGFloat {
        guard let collectionView = collectionView else { return 0 }
        let insets = collectionView.contentInset
        return collectionView.bounds.width - (insets.left + insets.right)
    }

    override var collectionViewContentSize: CGSize {
        CGSize(width: contentWidth, height: contentHeight)
    }

    // Required: builds and caches layout attributes for every item once.
    override func prepare() {
        guard cache.isEmpty, let collectionView = collectionView else { return }

        let columnWidth = contentWidth / CGFloat(numberOfColumns)
        var yOffsets = [CGFloat](repeating: 0, count: numberOfColumns)

        for item in 0..<collectionView.numberOfItems(inSection: 0) {
            let indexPath = IndexPath(item: item, section: 0)

            // Waterfall rule: place the next item in the currently shortest column.
            let column = yOffsets.firstIndex(of: yOffsets.min()!) ?? 0

            let itemWidth = columnWidth - cellPadding * 2
            let itemHeight = delegate?.collectionView(collectionView, heightForItemAt: indexPath, width: itemWidth) ?? 100

            let frame = CGRect(x: CGFloat(column) * columnWidth, y: yOffsets[column],
                              width: columnWidth, height: itemHeight + cellPadding * 2)
            let insetFrame = frame.insetBy(dx: cellPadding, dy: cellPadding)

            let attributes = UICollectionViewLayoutAttributes(forCellWith: indexPath)
            attributes.frame = insetFrame
            cache.append(attributes)

            contentHeight = max(contentHeight, frame.maxY)
            yOffsets[column] = frame.maxY
        }
    }

    // Required: which cached attributes intersect the visible rect (drives what's actually drawn).
    override func layoutAttributesForElements(in rect: CGRect) -> [UICollectionViewLayoutAttributes]? {
        cache.filter { $0.frame.intersects(rect) }
    }

    // Required: attributes for one index path (used for insert/delete/move animations).
    override func layoutAttributesForItem(at indexPath: IndexPath) -> UICollectionViewLayoutAttributes? {
        cache[indexPath.item]
    }

    // Recompute when the width changes (rotation, split view resize, size class change).
    override func shouldInvalidateLayout(forBoundsChange newBounds: CGRect) -> Bool {
        newBounds.width != collectionView?.bounds.width
    }

    // Clears the cache so prepare() rebuilds it after an invalidation (bounds change, reloadData).
    override func invalidateLayout() {
        cache.removeAll()
        contentHeight = 0
        super.invalidateLayout()
    }
}

Using it: assign the layout, set the delegate, and return each item's target height (e.g. from an image's aspect ratio).

final class WaterfallViewController: UIViewController {
    private var collectionView: UICollectionView!
    private let photos: [Photo] = Photo.samples

    override func viewDidLoad() {
        super.viewDidLoad()

        let layout = PinterestLayout()
        layout.delegate = self
        layout.numberOfColumns = 2

        collectionView = UICollectionView(frame: view.bounds, collectionViewLayout: layout)
        collectionView.dataSource = self
        collectionView.register(PhotoCell.self, forCellWithReuseIdentifier: PhotoCell.reuseID)
        view.addSubview(collectionView)
    }
}

extension WaterfallViewController: PinterestLayoutDelegate {
    func collectionView(_ collectionView: UICollectionView, heightForItemAt indexPath: IndexPath, width: CGFloat) -> CGFloat {
        let aspectRatio = photos[indexPath.item].size.height / photos[indexPath.item].size.width
        return width * aspectRatio   // preserves each photo's natural proportions
    }
}

Gotchas

  • Self-sizing (estimated size) requires the cell's contentView to have a complete, unambiguous constraint chain from top to bottom — a missing constraint makes the estimate become the final size (cells look clipped or too tall).
  • Flow layout's sizeForItemAt is called frequently during scrolling/rotation; keep the size computation cheap (no layout passes or string measurement on every call — cache computed sizes on the model).
  • Compositional layout's .estimated sizing invalidates and re-measures after the cell is displayed, which can cause a visible "jump" on first appearance for content that differs a lot from the estimate — pick a realistic estimate to minimize it.
  • Custom layouts must invalidate correctly on bounds change (shouldInvalidateLayout(forBoundsChange:)) or rotation/size-class changes will leave stale frames.

Common Interview Questions

Q: How do you support cells of different sizes in the same section with compositional layout? A: Model the section as nested NSCollectionLayoutItem/NSCollectionLayoutGroup objects, giving each item its own fractional/absolute/estimated width and height — different items in the same group can have different dimensions without a delegate callback.

Q: What's the difference between .estimated and .absolute sizing? A: .absolute is a fixed point value; .estimated gives the layout engine a starting guess and then lets Auto Layout (via the cell's constraints) resolve the real size after the cell is created — needed for content-driven (self-sizing) cells.

Q: Why would you write a custom UICollectionViewLayout instead of using compositional layout? A: When placement can't be expressed as rows/columns with fixed proportions — e.g. a Pinterest-style waterfall where each item goes into whichever column currently has the least height — compositional layout's group model can't express that, so you compute attributes manually in prepare().

Q: What breaks if a self-sizing cell's constraints are incomplete? A: Auto Layout can't resolve an intrinsic content size, so the layout falls back to the estimated size as final — cells render clipped, overlapping, or with wrong spacing, and it can look fine at first glance until content varies.

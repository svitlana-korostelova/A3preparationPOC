2.2.2.9. How do you choose between UITableView and UICollectionView for a given UI?

  • Rule of thumb: use UITableView for a single-column list of full-width rows (settings, chat threads, simple feeds) — swipe actions, section index titles, and grouped/inset styles come for free. Use UICollectionView for anything else: grids, multi-column layouts, horizontal carousels, or variable/mixed cell sizes.
  • The two have converged a lot: both support diffable data sources, self-sizing cells, prefetching, and cell registration APIs, and UICollectionViewCompositionalLayout can reproduce a plain list (.list(using:), iOS 14+) — so today it's mostly a layout decision, not a data-source-capability decision.
CriterionUITableViewUICollectionView
Layout shapeFixed: one column, full-width rowsArbitrary: grid, multi-column, horizontal, custom via UICollectionViewLayout
Built-in behaviorsSwipe actions, section index (A–Z), edit mode/reordering, grouped/inset stylesNone of these out of the box — must be built (though swipe actions can be added via UISwipeActionsConfiguration too)
Cell sizingRow height only (fixed/automatic)Full 2D size control per item, per section
Setup effortLowHigher (need a layout object, even if it's just compositional "list")
Modern replacementCan be fully replaced by UICollectionViewCompositionalLayout.list(using:) when you also want grid/list sections mixed in the same screenN/A

Gotcha: don't fake a grid inside UITableView with horizontal stack views in each row — it breaks down for dynamic counts and independent scrolling. If you need mixed sections (e.g. a grid section plus a list section), use one UICollectionView with UICollectionViewCompositionalLayout(sectionProvider:); a table view can't vary column count or scroll direction per section. In SwiftUI, the same reasoning maps to List vs LazyVGrid/LazyHGrid.

Common Interview Questions

Q: Is there anything a UITableView can do that a UICollectionView cannot? A: Not really since iOS 14 — UICollectionLayoutListConfiguration/.list(using:) gives collection views swipe actions, accessories, separators, and index titles, so a collection view can fully subsume a table view's behavior while also supporting non-list sections.

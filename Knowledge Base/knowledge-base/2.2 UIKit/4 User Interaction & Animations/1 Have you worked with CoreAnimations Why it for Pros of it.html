Have you worked with CoreAnimations? Why it for? Pros of it

Yes - Core Animation underlies every UIView animation: each UIView is backed by a CALayer, and animating frame/alpha/transform is Core Animation interpolating layer properties on a separate render server, off the main thread.

Why reach for it directly (CALayer/CABasicAnimation) instead of UIView.animate:

  • Fine-grained control: keyframes, timing functions, springs, groups, explicit vs implicit animations.
  • Animate properties UIView doesn't expose (shadowPath, cornerRadius, strokeEnd on CAShapeLayer).
  • GPU-driven via the render server - stays smooth even if the main thread briefly stalls.
  • CAGradientLayer, CAReplicatorLayer, CAEmitterLayer for effects that would be expensive to hand-draw.

Pros: declarative (describe start/end/timing, not per-frame logic), hardware accelerated, decoupled model/presentation layers enable mid-flight introspection.

Trade-offs: layer-tree debugging is harder than view debugging; mixing Auto Layout (constraint-driven) with direct layer animation (frame-driven) can fight each other; the presentation layer doesn't update the model layer automatically, so final state must be set explicitly.

What are best practices for handling multiple gestures on the same view?

  • Use the delegate, not ordering tricks: implement gestureRecognizer(_:shouldRecognizeSimultaneouslyWith:) to explicitly allow/deny simultaneous recognition (e.g. pinch + rotate together, but not pan + tap).
  • Model conflicts with require(toFail:) for mutually exclusive gestures (e.g. single tap waiting for double-tap to fail).
  • One recognizer per concern - compose behavior instead of overloading a single recognizer's state machine with unrelated logic.
  • Set cancelsTouchesInView/delaysTouchesBegan deliberately so a container gesture doesn't swallow touches meant for a subview's control.
  • Scope gestures to the smallest view that needs them to reduce accidental overlap with parent/scroll view gestures.
  • Use gestureRecognizer(_:shouldReceive:) to exclude specific touches/subviews (e.g. don't let a container's tap fire when tapping a nested button).
  • Prefer built-in gestures (UIPanGestureRecognizer already reports velocity/translation) over hand-rolled touch tracking; reserve raw touchesBegan overrides for genuinely custom multi-touch logic.

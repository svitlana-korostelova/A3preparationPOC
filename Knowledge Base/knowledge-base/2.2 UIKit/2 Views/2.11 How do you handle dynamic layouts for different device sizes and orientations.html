2.11. How do you handle dynamic layouts for different device sizes and orientations?

  • Relative, not fixed, constraints: anchor to `safeAreaLayoutGuide`/`layoutMarginsGuide`, use multipliers/ratios instead of hardcoded widths, so layout scales instead of breaking on different screen sizes.
  • Size classes over raw device/orientation checks: `UITraitCollection.horizontalSizeClass`/`verticalSizeClass` describe available space (compact/regular) — an iPad in Split View or Slide Over can be compact-width in landscape, so checking orientation or `UIDevice.userInterfaceIdiom` directly is brittle across multitasking/Stage Manager/folding devices.
  • React to trait changes: override `traitCollectionDidChange(_:)` (or the iOS 17+ `registerForTraitChanges` API) to re-flow layout, e.g. flip a `UIStackView`'s axis.
  • React to rotation/size transitions: `viewWillTransition(to:with:)` + the transition coordinator to animate constraint changes alongside the rotation.
  • Content priorities: set hugging/compression-resistance so labels/images adapt gracefully instead of ambiguous-constraint warnings across screen widths.
  • Dynamic Type / accessibility: `adjustsFontForContentSizeCategory`, scalable metrics (`UIFontMetrics`), and stack views that switch axis at large text sizes — layout must flex for content size, not just screen size.
  • Adaptive containers: `UISplitViewController` for regular-width (iPad) vs. stacked navigation on compact (iPhone), driven by the same size-class mechanism.
override func traitCollectionDidChange(_ previous: UITraitCollection?) {
  super.traitCollectionDidChange(previous)
  stack.axis = traitCollection.horizontalSizeClass == .compact ? .vertical : .horizontal
}

override func viewWillTransition(to size: CGSize, with coordinator: UIViewControllerTransitionCoordinator) {
  coordinator.animate(alongsideTransition: { _ in
    self.imageWidthConstraint.constant = size.width * 0.5
    self.view.layoutIfNeeded()
  })
}

Common Interview Questions

Q: Size classes vs. orientation checks — why prefer size classes? A: Size classes reflect actual available space, which can change independent of device rotation (multitasking, Slide Over, Stage Manager); orientation checks conflate "device rotated" with "space available" and break on iPad/multitasking.

Q: When would you use viewWillTransition vs traitCollectionDidChange? A: `viewWillTransition` is for size-driven, animated transitions (rotation, split-view resize) via the transition coordinator; `traitCollectionDidChange` fires for any trait change (size class, Dark Mode, Dynamic Type) even without a size-animated transition.

Q: How do you test this without a physical device farm? A: Xcode Previews across device presets, Simulator's rotate/Slide Over/Split View, and the Accessibility Inspector to step through Dynamic Type sizes.

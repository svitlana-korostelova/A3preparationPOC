2.3. What is transformation matrix?

Core idea: A transformation matrix encodes geometric operations (translate, scale, rotate, skew, perspective) as a single matrix that's applied to a view/layer's coordinate space when rendering. It changes where/how content is drawn on screen without touching frame/bounds/Auto Layout — the layout system still thinks the view is at its original frame; only the presentation is transformed.

CGAffineTransform CATransform3D
Lives on UIView.transform CALayer.transform
Dimensions 2D (3×3 matrix, last column implicit 0 0 1) 3D (4×4 matrix) — supports z translation, rotation around x/y, perspective
Common ops translate, scale, rotate, skew all of the above + 3D rotation, perspective (m34)
Applied around view.center / layer's anchorPoint layer's anchorPoint
Interop CATransform3DMakeAffineTransform / CATransform3DGetAffineTransform convert between them 
// CGAffineTransform — 2D, on UIView
view.transform = .identity
view.transform = CGAffineTransform(translationX: 50, y: 0)
view.transform = view.transform.scaledBy(x: 1.2, y: 1.2)          // combine
view.transform = view.transform.rotated(by: .pi / 4)

UIView.animate(withDuration: 0.3) {
    view.transform = CGAffineTransform(scaleX: 0.9, y: 0.9)
}

// CATransform3D — 3D, on CALayer, e.g. flip/perspective card animation
var transform = CATransform3DIdentity
transform.m34 = -1 / 500                 // perspective (further = smaller)
transform = CATransform3DRotate(transform, .pi / 4, 0, 1, 0)  // rotate around Y axis
view.layer.transform = transform

Matrix form (affine, 2D):

| a  b  0 |      x' = a*x + c*y + tx
| c  d  0 |  →   y' = b*x + d*y + ty
| tx ty 1 |

a,d = scale, b,c = rotation/skew, tx,ty = translation — this is exactly why compound transforms (scale + rotate + translate) can be combined by matrix multiplication instead of applying steps separately.

Common Interview Questions

Q: Does changing transform update frame/constraints? A: No — frame becomes derived/undefined when a non-identity transform is applied (Apple docs warn against reading frame on a transformed view); Auto Layout still lays out based on bounds/center as if untransformed, then the transform is applied on top at render time.

Q: Why use transform instead of animating frame? A: transform is GPU-accelerated (pure matrix math on the render layer) and doesn't retrigger layout; animating frame/constraints can be more expensive and can fight Auto Layout.

Q: How do you reset a transform? A: Set it back to .identity (CGAffineTransform.identity / CATransform3DIdentity) — never try to "undo" by hand-inverting unless you specifically need the inverse matrix (CGAffineTransform.inverted()).

Q: 2D vs 3D — when do you need CATransform3D? A: When you need depth (z translation/rotation) or perspective, e.g. flip transitions, card-flip animations, parallax — plain CGAffineTransform can't represent perspective or out-of-plane rotation.

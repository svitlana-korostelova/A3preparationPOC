2.2.6.1.2. How do you implement state restoration in a UIKit app?

State restoration brings the user back to the same screen after the system killed the app in the background. It is not a cache for data. Save only where the user was: IDs, selected tab, scroll position, draft text. Load the real data again from your store.

Modern way (iOS 13+, scenes)

  • When a scene goes to the background, UIKit calls stateRestorationActivity(for:) on your scene delegate. Return an NSUserActivity that holds a small userInfo dictionary.
  • UIKit saves it in UISceneSession.stateRestorationActivity.
  • On next launch, read it in scene(_:willConnectTo:options:) and rebuild the navigation stack.
  • UIKit asks for it every time the scene goes to the background, so return the current state each time.
final class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?

    func scene(_ scene: UIScene,
               willConnectTo session: UISceneSession,
               options connectionOptions: UIScene.ConnectionOptions) {
        guard let windowScene = scene as? UIWindowScene else { return }
        let root = RootTabBarController()
        let window = UIWindow(windowScene: windowScene)
        window.rootViewController = root
        window.makeKeyAndVisible()
        self.window = window

        if let activity = session.stateRestorationActivity {
            root.restore(from: activity)
        }
    }

    func stateRestorationActivity(for scene: UIScene) -> NSUserActivity? {
        (window?.rootViewController as? RootTabBarController)?.makeRestorationActivity()
    }
}

extension RootTabBarController {
    static let activityType = "com.example.app.restoration"

    func makeRestorationActivity() -> NSUserActivity {
        let activity = NSUserActivity(activityType: Self.activityType)
        activity.userInfo = ["tab": selectedIndex, "orderID": currentOrderID ?? ""]
        return activity
    }

    func restore(from activity: NSUserActivity) {
        guard activity.activityType == Self.activityType else { return }
        selectedIndex = activity.userInfo?["tab"] as? Int ?? 0
        if let id = activity.userInfo?["orderID"] as? String, !id.isEmpty {
            showOrder(id: id) // push the detail screen, then load data by ID
        }
    }
}

Legacy way (iOS 6–12, app delegate)

  • Set restorationIdentifier on every view controller in the path. Without it, that branch is skipped.
  • Opt in with application(_:shouldSaveSecureApplicationState:) and application(_:shouldRestoreSecureApplicationState:).
  • Override encodeRestorableState(with:) and decodeRestorableState(with:) in each controller. Call super.
  • Controllers made in code need UIViewControllerRestoration or application(_:viewControllerWithRestorationIdentifierPath:coder:).
  • Use it only when you must support old iOS. Scenes and NSUserActivity are the current path.

SwiftUI

@SceneStorage saves small values per scene and restores them automatically. It is the same idea with less code. In a UIKit + SwiftUI app, one place should own restoration, to avoid two sources of truth.

Follow-up questions

  • When is state not restored? When the user force-quits the app from the app switcher (the system drops the saved state), after a crash on launch, after a reboot or a long time, or when the app version changed and you chose to ignore old state.
  • How is it different from handoff or deep links? They use NSUserActivity too, but come from outside and carry intent ("open order 42"). Restoration is internal and carries position. Keep one routing function that both can call.
  • What must you not put in the saved state? Large models, images, secrets (tokens, passwords). The state is saved to disk and must stay small, or launch gets slow.
  • How do you test it? Run the app, go deep, press Home, stop from Xcode, then run again from the home screen (not from Xcode). Stopping from Xcode keeps the state. Force-quitting from the app switcher drops it.
  • What if the saved ID no longer exists? Validate on restore, fall back to the root screen, and never crash on a missing object.

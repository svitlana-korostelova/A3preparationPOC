Storyboard vs XIB vs NIB

A NIB is the umbrella/legacy term for a serialized Interface-Builder view hierarchy; a XIB is the modern XML source for a single NIB, typically one view/view controller/cell; a Storyboard holds many scenes plus the segues/relationships between them, compiled into one .storyboardc bundle.

AspectStoryboardXIB/NIB
ScopeMultiple scenes + flowSingle view/cell/component
Git diffsLarge XML, frequent merge conflictsSmall, easier to review
ReusePoor - hard to reuse one scene elsewhereGreat for reusable cells/views (UINib(nibName:))
Load costWhole graph parsed at first loadLightweight, loads only what's needed
NavigationSegues built-in but hidden in IBNavigation done explicitly in code
ModularityHard to split across frameworksEasy to ship inside a framework/module

Senior opinion: XIBs for reusable cells/components, code (or SwiftUI) for view controllers/navigation - keeps diffs reviewable, navigation unit-testable, and avoids hidden segue logic. Storyboards are fine for small apps/prototypes but scale poorly with team size.

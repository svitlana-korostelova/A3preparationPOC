2.2.4.6. How to change target action event?

A UIControl can send actions for control events such as .touchUpInside. Remove the old target/action pair, then add the new one:

// Remove the previous target/action pair
let oldTarget = Handler()
let newTarget = Handler()
button.removeTarget(oldTarget, action: #selector(Handler.didTap(_:)), for: .touchUpInside)

// Add a new one
button.addTarget(newTarget, action: #selector(Handler.didTap(_:)), for: .touchUpInside)

// Check which actions are registered for this target and event
let actions = button.actions(forTarget: newTarget, forControlEvent: .touchUpInside)

The handler must be exposed to Objective-C, for example:

final class Handler: NSObject {
    @objc func didTap(_ sender: UIButton) {
        // Handle the tap
    }
}
  • Adding the same target/action/event more than once is safe; UIKit calls that action once for the event. Remove the old pair when replacing it with a different target or action.
  • The control does not own its target. Keep the target alive while it should handle events; passing nil as the target asks UIKit to search the responder chain.
// iOS 14+: closure-based, no target/selector needed
let action = UIAction { _ in print("tapped") }
button.addAction(action, for: .touchUpInside)
button.removeAction(action, for: .touchUpInside)

Follow-up questions

  • What if the target is deallocated? The control does not keep the target alive, so don't rely on that object receiving the action. Remove its registration when it is no longer needed. Passing nil intentionally asks UIKit to search the responder chain.
  • .touchUpInside vs. .primaryActionTriggered? .touchUpInside is for a touch released inside the control. .primaryActionTriggered represents its primary action and can support other input methods, such as keyboard activation, depending on the control and platform.
  • How can you test a button action? Call button.sendActions(for: .touchUpInside) and assert that the expected handler or callback ran. No physical tap is needed.

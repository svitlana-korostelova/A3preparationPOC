2.2.4.7. How do gesture recognizers interact with the responder chain?

Gesture recognizers are not part of the responder chain. They observe touches on their view and its subviews while UIKit also sends the touch sequence to the hit-test view.

  • Recognizers attached to the hit-test view or one of its ancestors can observe the same touch.
  • By default, when a recognizer succeeds, cancelsTouchesInView is true. UIKit then cancels touch delivery to the view; this can explain why a view's touchesBegan or later touch methods do not receive the full sequence.
  • delaysTouchesBegan and delaysTouchesEnded control whether the recognizer delays sending those touch phases to the view while it decides.
  • Use UIGestureRecognizerDelegate methods or require(toFail:) to control whether recognizers can succeed together or one must fail first.

touchesBegan(_:with:), touchesMoved(_:with:), touchesEnded(_:with:), and touchesCancelled(_:with:) are UIResponder methods you override directly on a UIView (or view controller) subclass, rather than attaching a separate gesture-recognizer object. Reach for them when you need the raw touch stream — for example free-hand drawing, custom multi-touch handling, or tracking several simultaneous touches — cases a built-in gesture recognizer does not cover. Because a successful gesture recognizer on the same view cancels delivery by default (cancelsTouchesInView == true), avoid mixing both approaches on one view unless that setting is turned off.

The comments mark each phase of the touch sequence:

final class DrawingView: UIView {
    private var currentPath: UIBezierPath?

    override func touchesBegan(_ touches: Set<UITouch>, with event: UIEvent?) {
        // Called once when a finger first touches this view; start a new path at that point.
        guard let touch = touches.first else { return }
        let path = UIBezierPath()
        path.move(to: touch.location(in: self))
        currentPath = path
    }

    override func touchesMoved(_ touches: Set<UITouch>, with event: UIEvent?) {
        // Called repeatedly while the finger drags; extend the path and redraw.
        guard let touch = touches.first else { return }
        currentPath?.addLine(to: touch.location(in: self))
        setNeedsDisplay()
    }

    override func touchesEnded(_ touches: Set<UITouch>, with event: UIEvent?) {
        // Called when the finger lifts up normally; the stroke is complete.
        currentPath = nil
    }

    override func touchesCancelled(_ touches: Set<UITouch>, with event: UIEvent?) {
        // Called when the system interrupts the touch (e.g. an incoming call or a gesture recognizer taking over).
        // Treat this like an abrupt touchesEnded: discard the in-progress stroke instead of keeping it.
        currentPath = nil
    }
}

Hit-testing chooses the view that receives the touch. Gesture recognizers separately examine that touch and can recognize a gesture or cancel delivery to the view. If the view receives an event, the responder chain can then pass it to the next responder.

The comments below show where each setting changes touch delivery:

let tapRecognizer = UITapGestureRecognizer(target: self, action: #selector(handleTap))
// Let the underlying view still receive touchesBegan/Ended even after the tap recognizes.
tapRecognizer.cancelsTouchesInView = false
view.addGestureRecognizer(tapRecognizer)

let doubleTapRecognizer = UITapGestureRecognizer(target: self, action: #selector(handleDoubleTap))
doubleTapRecognizer.numberOfTapsRequired = 2
view.addGestureRecognizer(doubleTapRecognizer)

// Make the single tap wait: it only succeeds once the double tap has failed.
tapRecognizer.require(toFail: doubleTapRecognizer)

Use UIGestureRecognizerDelegate when two recognizers should be allowed to recognize at the same time, such as a pan on a child view running together with a pinch on its parent:

extension ViewController: UIGestureRecognizerDelegate {
    func gestureRecognizer(
        _ gestureRecognizer: UIGestureRecognizer,
        shouldRecognizeSimultaneouslyWith otherGestureRecognizer: UIGestureRecognizer
    ) -> Bool {
        // Allow the pan and the pinch recognizer to recognize together instead of one blocking the other.
        return (gestureRecognizer is UIPanGestureRecognizer && otherGestureRecognizer is UIPinchGestureRecognizer)
            || (gestureRecognizer is UIPinchGestureRecognizer && otherGestureRecognizer is UIPanGestureRecognizer)
    }
}

Follow-up questions

  • Why might touchesBegan not fire? The view may not be the hit-test result, interaction may be disabled, or a gesture recognizer may delay or cancel the touch delivery.
  • How can a scroll view pan while a child button still receives taps? A short touch activates the button. If the finger moves enough to start scrolling, the pan recognizer takes over and cancels the button touch.
  • What if the recognizer's view is removed during a gesture? UIKit cancels the in-progress touch sequence. Handle the recognizer's cancelled state to clean up any temporary UI or state.

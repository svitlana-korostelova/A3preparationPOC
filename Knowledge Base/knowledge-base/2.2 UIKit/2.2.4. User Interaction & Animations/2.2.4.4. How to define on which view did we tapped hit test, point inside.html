2.2.4.4. How to define on which view did we tapped? hit test, point inside

UIKit finds the view for a touch by hit-testing, starting at the window:

  1. A view is skipped if it is hidden, has alpha < 0.01, has interaction disabled, or the touch is outside its bounds.
  2. If eligible, UIKit checks its subviews from front to back, converting the touch point into each view's coordinate space.
  3. The deepest eligible view containing the point is returned as the hit-test view.

Override point(inside:with:) to enlarge the area UIKit checks for this view and its subviews. Override hitTest(_:with:) only when you need to change which view receives a touch. In this pass-through overlay example, super.hitTest returns the deepest child that contains the touch, or the overlay itself if no child matches. Returning nil when only the overlay was hit lets a view behind it receive the touch. To make the overlay receive that touch, return self instead.

The comments above the code explain what each method returns:

  • point(inside:with:) returns true if the touch is in the expanded bounds; otherwise it returns false.
  • hitTest(_:with:) returns a child view, or nil to let a view behind this overlay receive the touch.
override func point(inside point: CGPoint, with event: UIEvent?) -> Bool {
    // Return true when the touch is inside the expanded tap area.
    let expandedBounds = bounds.insetBy(dx: -20, dy: -20)
    return expandedBounds.contains(point)
}

override func hitTest(_ point: CGPoint, with event: UIEvent?) -> UIView? {
    // Returns the deepest child that contains the touch, or this view if no child matches.
    let hitView = super.hitTest(point, with: event)
    // Return the child; return nil when only this overlay was hit, passing through to what's behind.
    return hitView === self ? nil : hitView
}

Follow-up questions

  • Why might a button not respond where it appears on screen? Its tappable bounds may not cover that point, a parent may reject the touch first, or another view may be in front of it.
  • How do transforms and Auto Layout affect hit-testing? Auto Layout only computes the view's untransformed bounds and center. If a transform (scale, rotation, translation) is applied afterward, UIKit hit-tests against the view as it actually appears on screen, not its original layout rectangle. Because of this, a view's frame becomes unreliable once a transform is applied — check bounds and center instead, or convert points with convert(_:to:)/convert(_:from:) to get accurate coordinates.
  • How can a view pass touches through? For an overlay, return nil from hitTest(_:with:) when the result is the overlay itself, as shown above. Its interactive subviews can still receive touches.

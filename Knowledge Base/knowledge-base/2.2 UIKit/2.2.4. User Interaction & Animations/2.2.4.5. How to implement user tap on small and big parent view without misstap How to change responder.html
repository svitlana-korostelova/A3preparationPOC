2.2.4.5. How to implement user tap on small and big parent view without misstap? How to change responder?

If a small button sits inside a larger view, make the button easier to tap without changing its visible size:

  • Override the button's point(inside:with:) to expand its tappable area.
  • Make sure the button's superview also includes the expanded area in its hit-test region; UIKit doesn't normally hit-test outside a superview's bounds.
  • Use a custom hitTest(_:with:) only when the default front-to-back view order is not what you need. Avoid routing every parent tap to a child, as that can steal taps from nearby controls.
override func point(inside point: CGPoint, with event: UIEvent?) -> Bool {
    bounds.insetBy(dx: -10, dy: -10).contains(point)
}

Changing the first responder is separate from choosing which view gets a touch. For example, a text field can give up first-responder status so another field can show the keyboard:

// Force first responder change (e.g. text field handoff)
nextTextField.becomeFirstResponder()

Follow-up questions

  • What tap target size does Apple recommend? Apple's iOS guidance recommends at least 44 × 44 points. Prefer making the control that size; if that isn't possible, expand its hit area with point(inside:with:) and avoid overlapping nearby targets.
  • How do you keep a scroll view's pan gesture from stealing a button tap? Usually you don't need to: a short tap activates the button, while a drag lets the scroll view pan and cancels the button touch. Avoid adding a competing parent gesture recognizer; if you do, filter out touches on the button with its delegate.
  • What does resignFirstResponder() do? It asks the current responder to stop being first responder. If it is a text field, the keyboard normally hides. Hiding the keyboard alone does not necessarily end text editing; use resignFirstResponder() or endEditing(_:) to end it.

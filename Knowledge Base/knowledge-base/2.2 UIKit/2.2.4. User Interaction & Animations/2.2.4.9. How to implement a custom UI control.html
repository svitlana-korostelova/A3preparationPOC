2.2.4.9. How to implement a custom UI control?

Subclass UIControl instead of UIView when you want a reusable component that behaves like a built-in control (button, switch, slider) and works with the standard target-action pattern. UIControl gives you touch tracking and sendActions(for:) for free, so callers can attach handlers with addTarget(_:action:for:) exactly like they do with UIButton.

Steps to build one:

  1. Subclass UIControl and draw the control's appearance (with CALayers, UIView subviews, or draw(_:)).
  2. Override beginTracking(_:with:), continueTracking(_:with:), and endTracking(_:with:) to read touch locations and update internal state.
  3. Whenever the control's value changes, call sendActions(for:) with the matching UIControl.Event (e.g. .valueChanged, .touchUpInside) so every registered target gets notified.
  4. Expose the current value as a public property so consumers can read it outside of the action callback.

The comments in the code below mark where tracking starts, where the value updates while dragging, and where the action fires:

final class KnobControl: UIControl {
    // Current value in 0...1, clamped on every update.
    private(set) var value: CGFloat = 0

    private let trackLayer = CAShapeLayer()
    private let knobLayer = CAShapeLayer()

    override init(frame: CGRect) {
        super.init(frame: frame)
        layer.addSublayer(trackLayer)
        layer.addSublayer(knobLayer)
    }

    required init?(coder: NSCoder) { fatalError("init(coder:) has not been implemented") }

    override func beginTracking(_ touch: UITouch, with event: UIEvent?) -> Bool {
        // Update immediately so a single tap moves the knob to that point.
        updateValue(with: touch)
        return true
    }

    override func continueTracking(_ touch: UITouch, with event: UIEvent?) -> Bool {
        // Called repeatedly while the finger drags across the control.
        updateValue(with: touch)
        return true
    }

    override func endTracking(_ touch: UITouch?, with event: UIEvent?) {
        // Fire a final action so observers know dragging has stopped.
        sendActions(for: .touchUpInside)
    }

    private func updateValue(with touch: UITouch) {
        let location = touch.location(in: self)
        let newValue = min(1, max(0, location.x / bounds.width))
        guard newValue != value else { return }
        value = newValue
        setNeedsLayout()
        // Notify every target registered for .valueChanged, e.g. via addTarget(_:action:for:).
        sendActions(for: .valueChanged)
    }
}

Follow-up questions

  • Why subclass UIControl instead of UIView with a gesture recognizer? UIControl gives you the standard target-action API, built-in isEnabled/isSelected/isHighlighted states, and touch-tracking hooks, so the control behaves consistently with other UIKit controls and is easier for other developers to adopt.
  • When should continueTracking(_:with:) return false? Return false to cancel tracking, for example when the touch moves far outside the control's bounds and you want to treat the gesture as abandoned.
  • How do you support accessibility for a custom control? Set isAccessibilityElement = true, provide accessibilityLabel/accessibilityValue, and update accessibilityValue whenever value changes so VoiceOver announces the new state.

2.2.4.1. Have you worked with CoreAnimations? Why it for? Pros of it

Yes — Core Animation is what actually runs every UIView animation. Every UIView has a CALayer underneath it, and when you animate things like frame, alpha, or transform, Core Animation calculates each step and draws it on a separate process (the render server), not on the main thread.

Why use it directly (CALayer/CABasicAnimation) instead of UIView.animate:

  • More control: keyframes, custom timing curves, springs, grouped animations, and the choice between explicit and implicit animations.
  • Can animate properties UIView.animate can't touch, like shadowPath, cornerRadius, or strokeEnd on a CAShapeLayer.
  • Runs on the GPU through the render server, so it stays smooth even if the main thread is briefly busy.
  • Special layers like CAGradientLayer, CAReplicatorLayer, and CAEmitterLayer make effects easy that would be slow to draw by hand.

Pros:

  • Declarative: you just describe the start, end, and timing — no per-frame code to write.
  • Hardware accelerated, so it stays smooth even when the main thread is busy.
  • Keeps two versions of the layer (model and presentation), so you can check the current on-screen value while the animation is still running.

Trade-offs:

  • Harder to debug than views, since you're inspecting layers instead of the view hierarchy.
  • Auto Layout (works with constraints) and direct layer animation (works with frames) can fight each other if mixed carelessly.
  • The presentation layer doesn't update the model layer for you — you must set the final value yourself, or the layer snaps back once the animation ends.

Follow-up questions

  • How do you animate a property that isn't implicitly animatable on CALayer? Wrap it in an explicit CABasicAnimation with that key path, set fromValue/toValue, add it to the layer, and also set the model property to the final value yourself. Example for shadowPath, which UIView.animate snaps instead of animating:
let oldPath = UIBezierPath(rect: view.bounds)
let newPath = UIBezierPath(roundedRect: view.bounds, cornerRadius: 16)

let animation = CABasicAnimation(keyPath: "shadowPath")
animation.fromValue = oldPath.cgPath
animation.toValue = newPath.cgPath
animation.duration = 0.3
layer.add(animation, forKey: "shadowPath")
layer.shadowPath = newPath.cgPath // set model value so it doesn't snap back

2.2.5.1. How do you create and manage reusable custom cells?

Custom cells follow the same reuse pool as built-in cells: subclass, register, dequeue, and reset state on reuse.

1. Subclass and build the UI

Create a UITableViewCell/UICollectionViewCell subclass and lay out subviews in init(style:reuseIdentifier:) (or init(frame:) for collection cells). Expose a single configure(with:) entry point so all cell state flows from one place.

final class UserCell: UITableViewCell {
    static let reuseID = "UserCell"

    private let titleLabel = UILabel()
    private let avatarView = UIImageView()

    override init(style: UITableViewCell.CellStyle, reuseIdentifier: String?) {
        super.init(style: style, reuseIdentifier: reuseIdentifier)
        // build subviews + Auto Layout constraints once, here
    }

    required init?(coder: NSCoder) { fatalError() }

    func configure(with user: User) {
        titleLabel.text = user.name
        avatarView.image = user.avatar
    }

    override func prepareForReuse() {
        super.prepareForReuse()
        // clear anything configure(with:) may not overwrite (e.g. async image task)
        avatarView.image = nil
    }
}

2. Register and dequeue

Register the class (or nib) once, then always dequeue — never instantiate cells directly.

tableView.register(UserCell.self, forCellReuseIdentifier: UserCell.reuseID)

func tableView(_ tableView: UITableView, cellForRowAt indexPath: IndexPath) -> UITableViewCell {
    let cell = tableView.dequeueReusableCell(withIdentifier: UserCell.reuseID, for: indexPath) as! UserCell
    cell.configure(with: users[indexPath.row])
    return cell
}

3. Why prepareForReuse matters

UIKit keeps a small pool of offscreen cells per reuse identifier and recycles them as rows scroll into view. Because the same instance is reused, any state not explicitly reset in configure(with:) can leak from a previous row — the classic symptom is a stale image flashing before the new one loads. Reset mutable, async-driven state in prepareForReuse() (cancel in-flight image tasks, clear labels/accessories) so every cell starts from a known baseline.

Quick rules

  • One reuse identifier per cell type; register before the table/collection view is used.
  • Keep configure(with:) idempotent — safe to call on a dirty, reused instance.
  • Cancel async work (image downloads, decoding) in prepareForReuse() to avoid wrong-cell updates.
  • For collection views with varying layouts, also reset UICollectionReusableView supplementary views the same way.

2.2.5.3. What’s the best way to support both light and dark mode in your UI?

Lean on the system's dynamic color/image infrastructure instead of branching on the current appearance — UIKit then handles switching automatically, including live updates when the user changes Settings or uses an app-specific override.

1. Use semantic system colors first

.label, .secondaryLabel, .systemBackground, .separator, etc. already adapt to light/dark (and high-contrast) automatically — prefer them over hardcoded hex values.

view.backgroundColor = .systemBackground
titleLabel.textColor = .label
divider.backgroundColor = .separator

2. Define custom dynamic colors

For brand colors, add them to the Asset Catalog with "Any, Dark" appearance variants, or build them in code with a dynamic provider.

extension UIColor {
    static let brandBackground = UIColor { traits in
        traits.userInterfaceStyle == .dark
            ? UIColor(red: 0.11, green: 0.11, blue: 0.12, alpha: 1)
            : UIColor(red: 0.98, green: 0.98, blue: 0.96, alpha: 1)
    }
}

3. Images

Give imageset assets separate "Any Appearance" / "Dark Appearance" variants in the catalog so UIImage(named:) resolves the right one automatically — no code changes needed.

4. React to appearance changes where needed

Anything outside UIKit's automatic handling — CALayer.backgroundColor (CGColor, not dynamic), Core Graphics drawing, cached snapshots — must be refreshed manually.

override func traitCollectionDidChange(_ previous: UITraitCollection?) {
    super.traitCollectionDidChange(previous)
    guard traitCollection.hasDifferentColorAppearance(comparedTo: previous) else { return }
    layer.borderColor = UIColor.separator.cgColor // CGColor doesn't auto-update
}

5. Test both modes

  • Simulator/device: Settings → Developer → Dark Appearance, or the Xcode debug bar's appearance toggle.
  • overrideUserInterfaceStyle on a view/window to force a mode for testing or per-screen opt-out.
  • Check Xcode's Color Assets preview and SwiftUI/UIKit previews in both appearances before shipping.

Quick rules

  • Never hardcode light-only hex colors for UI chrome — always go through semantic or custom dynamic colors.
  • Remember CGColor/CGImage are snapshots, not dynamic — refresh them in traitCollectionDidChange.
  • Test dark mode as a first-class configuration, not an afterthought.

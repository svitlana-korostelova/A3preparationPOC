2.2.7.2. How do you implement a split view in UIKit?

Rule: use UISplitViewController. It handles size classes, collapse/expand, and iPad multitasking for you. Build your own container only if the design is far from the system pattern.

Setup (iOS 14+ column API)

  • Create it with a style: .doubleColumn (list + detail) or .tripleColumn (sidebar + list + detail).
  • Set each column with setViewController(_:for:): .primary, .supplementary (triple only), .secondary. Wrap each one in a UINavigationController.
  • Optional .compact column: the screen shown on iPhone and compact width. If you skip it, the controller collapses the columns for you.
  • The split view controller must be the root view controller of a window (or a child in a container). Do not push it on a navigation stack.
  • Tune it with preferredDisplayMode, preferredSplitBehavior (.tile, .overlay, .displace), preferredPrimaryColumnWidth.
let split = UISplitViewController(style: .doubleColumn)
split.setViewController(UINavigationController(rootViewController: ListViewController()), for: .primary)
split.setViewController(UINavigationController(rootViewController: DetailViewController()), for: .secondary)
split.preferredDisplayMode = .oneBesideSecondary
split.preferredSplitBehavior = .tile
split.delegate = self
window.rootViewController = split

Show the detail

Do not push the detail yourself. Replace the secondary content and call show(.secondary). The controller decides what that means: it updates the detail column on iPad and pushes on iPhone.

func didSelect(_ item: Item) {
    let detail = DetailViewController(item: item)
    (split.viewController(for: .secondary) as? UINavigationController)?.setViewControllers([detail], animated: false)
    split.show(.secondary)
}

Control the collapsed start screen

On iPhone the controller picks the top screen when it collapses. The default can be an empty detail. Return .primary to start on the list:

func splitViewController(_ svc: UISplitViewController,
                         topColumnForCollapsingToProposedTopColumn proposed: UISplitViewController.Column) -> UISplitViewController.Column {
    .primary
}

Full minimal example

The snippets above use types that are not defined (ListViewController, Item, window, the delegate). This version is complete and compiles on iOS 17. The key points:

  • One object (SplitCoordinator) owns the split view controller, wires the list to the detail, and is the delegate.
  • The list does not know about the split view. It only calls onSelect.
  • The secondary column holds a placeholder detail, so iPad never shows an empty screen at start.
  • Keep the coordinator alive (here: a property of SceneDelegate). delegate is weak, so it would be released otherwise.
  • Scene setup: Info.plist needs UIApplicationSceneManifest with UISceneDelegateClassName set to this SceneDelegate (module-qualified name).
import UIKit

struct Item { let id: Int; let title: String }

// Primary column: the list
final class ListViewController: UITableViewController {
    var onSelect: ((Item) -> Void)?
    private let items = (1...20).map { Item(id: $0, title: "Item \($0)") }

    override func viewDidLoad() {
        super.viewDidLoad()
        title = "Items"
        tableView.register(UITableViewCell.self, forCellReuseIdentifier: "cell")
    }

    override func tableView(_ tv: UITableView, numberOfRowsInSection section: Int) -> Int { items.count }

    override func tableView(_ tv: UITableView, cellForRowAt indexPath: IndexPath) -> UITableViewCell {
        let cell = tv.dequeueReusableCell(withIdentifier: "cell", for: indexPath)
        cell.textLabel?.text = items[indexPath.row].title
        return cell
    }

    override func tableView(_ tv: UITableView, didSelectRowAt indexPath: IndexPath) {
        onSelect?(items[indexPath.row])
    }
}

// Secondary column: the detail
final class DetailViewController: UIViewController {
    private let text: String

    init(text: String) {
        self.text = text
        super.init(nibName: nil, bundle: nil)
    }
    required init?(coder: NSCoder) { fatalError("init(coder:) is not used") }

    override func viewDidLoad() {
        super.viewDidLoad()
        view.backgroundColor = .systemBackground
        title = text
        let label = UILabel()
        label.text = text
        label.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(label)
        NSLayoutConstraint.activate([
            label.centerXAnchor.constraint(equalTo: view.centerXAnchor),
            label.centerYAnchor.constraint(equalTo: view.centerYAnchor)
        ])
    }
}

// Owns the split view, connects list to detail, acts as delegate
final class SplitCoordinator: NSObject, UISplitViewControllerDelegate {
    let split = UISplitViewController(style: .doubleColumn)
    private let detailNav = UINavigationController(
        rootViewController: DetailViewController(text: "Select an item"))

    override init() {
        super.init()
        let list = ListViewController(style: .insetGrouped)
        list.onSelect = { [weak self] item in self?.show(item) }

        split.setViewController(UINavigationController(rootViewController: list), for: .primary)
        split.setViewController(detailNav, for: .secondary)
        split.preferredDisplayMode = .oneBesideSecondary
        split.preferredSplitBehavior = .tile
        split.delegate = self
    }

    private func show(_ item: Item) {
        detailNav.setViewControllers([DetailViewController(text: item.title)], animated: false)
        split.show(.secondary)   // iPad: updates detail. iPhone: pushes it.
    }

    // iPhone / compact: start on the list, not on the placeholder
    func splitViewController(
        _ svc: UISplitViewController,
        topColumnForCollapsingToProposedTopColumn proposedTopColumn: UISplitViewController.Column
    ) -> UISplitViewController.Column {
        .primary
    }
}

// The split view must be the window's root
final class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?
    private let coordinator = SplitCoordinator()   // strong ref: delegate is weak

    func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
               options connectionOptions: UIScene.ConnectionOptions) {
        guard let windowScene = scene as? UIWindowScene else { return }
        let window = UIWindow(windowScene: windowScene)
        window.rootViewController = coordinator.split
        window.makeKeyAndVisible()
        self.window = window
    }
}

Limits of UISplitViewController

  • Max 2 or 3 columns. The styles are .doubleColumn and .tripleColumn. No 4th pane.
  • Side by side only. No top/bottom split.
  • Layout rules belong to the system. Collapse and expand follow size classes. You cannot say "show both panes when width > 600". You can only tune it with preferredDisplayMode, preferredSplitBehavior and the column widths.
  • Column width is limited. You set preferred, minimum and maximum widths. There is no custom drag handle.
  • Collapse on iPhone is automatic. You influence it only through delegate methods (for example, the start column).
  • Should be a root controller. It is not meant to be pushed on a navigation stack or placed in a small area of a screen.
  • Limited visual control. The column toggle button, the sidebar look and the transitions are system-made.

Follow-up questions

  • Why does the user see an empty detail on iPhone? The collapse picked the secondary column without content. Implement the delegate method above, or show a real placeholder.
  • How do I know if it is one column or two? Check isCollapsed or the horizontalSizeClass. Do not check the device type: iPad in Split View or Slide Over is also compact.
  • What is the SwiftUI equivalent? NavigationSplitView (iOS 16+). Inside a UIKit app you can host it with UIHostingController.
  • When do I build a custom container instead? When the layout rules differ from the system ones, for example a fixed side panel with custom resize. Use child view controllers (see 2.2.1.6) and handle size changes yourself.

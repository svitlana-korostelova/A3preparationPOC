2.2.7.1. How do you implement a custom animation in UIKit?

Rule: pick the highest-level API that does the job. Drop to a lower level only when you need more control.

Which tool for which animation

  • View properties (alpha, transform, frame, colour): UIView.animate(withDuration:). For springs use UIView.animate(springDuration:bounce:) (iOS 17) or the older usingSpringWithDamping variant.
  • Interruptible, pausable, reversible: UIViewPropertyAnimator. You can pause, scrub with fractionComplete, and reverse. Use it for gesture-driven animation.
  • Layer or shape (path, stroke, shadow, corner radius): CABasicAnimation, CAKeyframeAnimation, CASpringAnimation on a CALayer (see 2.2.4.2).
  • Auto Layout changes: change the constraint, then call layoutIfNeeded() inside the animation block.
  • Between screens: a custom transition (below).
  • Custom modal look (bottom card, dimmed background): try UISheetPresentationController with detents first (iOS 15+). If it is not enough, subclass UIPresentationController and set modalPresentationStyle = .custom.

Custom transition between screens

Set transitioningDelegate (modal) or the navigation controller's delegate (push/pop). Return an object that conforms to UIViewControllerAnimatedTransitioning. For gesture-driven transitions also return a UIViewControllerInteractiveTransitioning, usually UIPercentDrivenInteractiveTransition (see 2.2.1.4).

final class FadeScaleAnimator: NSObject, UIViewControllerAnimatedTransitioning {
    func transitionDuration(using ctx: UIViewControllerContextTransitioning?) -> TimeInterval { 0.35 }

    func animateTransition(using ctx: UIViewControllerContextTransitioning) {
        guard let toView = ctx.view(forKey: .to) else { return }
        ctx.containerView.addSubview(toView)
        toView.alpha = 0
        toView.transform = CGAffineTransform(scaleX: 0.9, y: 0.9)

        UIView.animate(withDuration: transitionDuration(using: ctx), animations: {
            toView.alpha = 1
            toView.transform = .identity
        }, completion: { _ in
            ctx.completeTransition(!ctx.transitionWasCancelled) // always call, or the UI freezes
        })
    }
}

Use the animator only for push. Return nil for pop, so the system back animation and back swipe keep working:

func navigationController(_ nc: UINavigationController,
                          animationControllerFor operation: UINavigationController.Operation,
                          from: UIViewController, to: UIViewController) -> UIViewControllerAnimatedTransitioning? {
    operation == .push ? FadeScaleAnimator() : nil
}

Interactive part: drive the same animation with a pan gesture.

@objc func handlePan(_ g: UIPanGestureRecognizer) {
    guard let view = g.view else { return }
    let progress = min(max(g.translation(in: view).x / view.bounds.width, 0), 1)
    switch g.state {
    case .began:
        isInteracting = true
        navigationController?.popViewController(animated: true)
    case .changed:
        interaction.update(progress)            // interaction = UIPercentDrivenInteractiveTransition()
    case .ended, .cancelled:
        isInteracting = false
        (progress > 0.5 || g.velocity(in: view).x > 500) ? interaction.finish() : interaction.cancel()
    default: break
    }
}
// In the delegate: navigationController(_:interactionControllerFor:) returns isInteracting ? interaction : nil

Follow-up questions

  • Why do I need completeTransition? UIKit waits for it to finish the transition. Without it, the screen is stuck and gets no touches. Pass !transitionWasCancelled so a cancelled interactive transition is reported correctly.
  • Why does a CABasicAnimation snap back at the end? It animates only the presentation layer. The model value stays the same. Set the final value on the layer (layer.opacity = 1) when you add the animation.
  • Which properties are cheap to animate? transform and alpha are done by the GPU, no layout pass. Animating frame or constraints triggers layout every frame. Shadows without shadowPath and masks cause offscreen rendering.
  • Why use UIViewPropertyAnimator over UIView.animate? It can be interrupted, paused, reversed, and scrubbed. UIView.animate is fire-and-forget. For transitions, return it from interruptibleAnimator(using:).
  • What about users who turn on Reduce Motion? Check UIAccessibility.isReduceMotionEnabled and use a simple cross-fade instead of large movement.

2.2.7.3. How do you implement a non-standard navigation bar?

Rule: start with the appearance API. Hide or replace the system bar only if the design cannot be done any other way.

Options, from least to most work

  • Style only (colour, font, blur, no shadow): UINavigationBarAppearance. Set standardAppearance, scrollEdgeAppearance, compactAppearance, and compactScrollEdgeAppearance (iOS 15+), or the bar looks different at the top of a scroll view. Use navigationBar.tintColor for button colour. To style one screen only, use the same properties on navigationItem.
  • Custom content: navigationItem.titleView, leftBarButtonItems, rightBarButtonItems with UIBarButtonItem(customView:). Give custom views a size with Auto Layout, or they may collapse to zero.
  • Back button: backButtonDisplayMode = .minimal, or a custom image with appearance.setBackIndicatorImage(_:transitionMaskImage:). Both keep the back swipe.
  • Custom bar class: UINavigationController(navigationBarClass:toolbarClass:). Then set viewControllers yourself. Do not touch the bar's private subviews. They change between iOS versions.
  • Fully custom bar: hide the system bar (setNavigationBarHidden(true, animated:)) and add your own view. You lose the back swipe. Restore it as shown below. You also lose large titles and some accessibility support.
let appearance = UINavigationBarAppearance()
appearance.configureWithTransparentBackground()
appearance.titleTextAttributes = [.foregroundColor: UIColor.label]
navigationController?.navigationBar.standardAppearance = appearance
navigationController?.navigationBar.scrollEdgeAppearance = appearance
navigationController?.navigationBar.compactAppearance = appearance
navigationController?.navigationBar.compactScrollEdgeAppearance = appearance

Keep the back swipe when the system bar is hidden:

final class AppNavigationController: UINavigationController, UIGestureRecognizerDelegate {
    override func viewDidLoad() {
        super.viewDidLoad()
        setNavigationBarHidden(true, animated: false)
        interactivePopGestureRecognizer?.delegate = self
    }

    func gestureRecognizerShouldBegin(_ gestureRecognizer: UIGestureRecognizer) -> Bool {
        viewControllers.count > 1 // on the root screen the swipe would freeze navigation
    }
}

If only some screens need no bar, hide it per screen and restore it when leaving:

override func viewWillAppear(_ animated: Bool) {
    super.viewWillAppear(animated)
    navigationController?.setNavigationBarHidden(true, animated: animated)
}

override func viewWillDisappear(_ animated: Bool) {
    super.viewWillDisappear(animated)
    navigationController?.setNavigationBarHidden(false, animated: animated)
}

navigationBar vs navigationItem vs UIBarButtonItem

Short rule: the bar is the container (one per navigation controller). The item is the content (one per view controller). The bar shows the item of the top screen.

navigationBar (UINavigationBar)navigationItem (UINavigationItem)UIBarButtonItem
What it isThe view at the top of the screenA data object that describes what the bar shows for one screenOne button inside an item
OwnerUINavigationControllerEach UIViewControllerThe item (leftBarButtonItems, rightBarButtonItems, backBarButtonItem)
How manyOne, shared by all screens in the stackOne per screenMany per item
Use forLook of the whole app: colours, fonts, blur, prefersLargeTitles, back indicator imageContent of this screen: title, titleView, buttons, largeTitleDisplayMode, searchController, backButtonTitleActions: title or image, target-action, menu, or customView

Correct setup:

  • Global style goes to the bar. Set it once, in the navigation controller or at app start.
  • Screen content goes to navigationItem. Set it in viewDidLoad of that screen.
  • One-screen style override goes to navigationItem.standardAppearance (and the other three). It wins over the bar for this screen only.
  • Back button text belongs to the previous screen. Set backButtonTitle or backBarButtonItem on the screen that pushes, not on the pushed screen.
// Navigation controller: one style for the whole stack
let nav = UINavigationController(rootViewController: ListViewController())
nav.navigationBar.prefersLargeTitles = true
nav.navigationBar.tintColor = .systemBlue
nav.navigationBar.standardAppearance = appearance
nav.navigationBar.scrollEdgeAppearance = appearance

// View controller: content of this screen
override func viewDidLoad() {
    super.viewDidLoad()
    navigationItem.title = "Orders"
    navigationItem.largeTitleDisplayMode = .never
    navigationItem.backButtonTitle = "Back" // shown on the NEXT screen
    navigationItem.rightBarButtonItem = UIBarButtonItem(
        systemItem: .add, primaryAction: UIAction { [weak self] _ in self?.addTapped() })
}

Common mistakes:

  • Setting the title or buttons on navigationBar. The bar is shared, so the next screen overwrites them. Use navigationItem.
  • Using navigationController?.navigationBar in init. The controller is nil until the screen is pushed. navigationItem works at any time.

Follow-up questions

  • Why set the title on navigationItem and not on the bar? The bar is one shared view. The item belongs to the screen, and the bar swaps to it during push and pop. This also makes the push animation correct.
  • Why does the back swipe stop working with a custom bar or custom back button? The system pop gesture is tied to the standard bar and its delegate. Hiding the bar or replacing leftBarButtonItem disables it. Fix it with the delegate above. Do not enable it on the root screen.
  • Why does the nav bar look different when I scroll? scrollEdgeAppearance is used at the top of the scroll view, standardAppearance after scrolling. Set all appearances to get the same look at every scroll position.
  • Why did my bar colour stop working after iOS 15? barTintColor and isTranslucent no longer apply to the scroll-edge state. Use UINavigationBarAppearance with backgroundColor.
  • Custom bar view or system bar: which is better? System bar: Dynamic Type, large titles, accessibility, and iOS updates come free. Custom bar gives full design freedom but you own all of it. Prefer the appearance API unless the design needs more.

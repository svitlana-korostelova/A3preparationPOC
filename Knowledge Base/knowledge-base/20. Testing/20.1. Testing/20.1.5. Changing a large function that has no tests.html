20.1.5. Changing a large function that has no tests

You need one part of a large function. It has no tests, you do not understand all of it, and you may only change this one file. How do you approach it?

Say this: I do not rewrite it. I pin the current behaviour with characterization tests, then I extract only the part I need, in small steps, and I check with the person who last owned the file. On a legacy screen, the refactor itself waits for approval.

  1. Find the seam without editing behaviour. What goes in, what comes out, what it calls. git log -L and git blame on that function. Ask the author if they are still on the team. The history is the spec you do not have.
  2. Write characterization tests first. They lock what the function does today, including the odd cases, not what you wish it did. Put them in the test target. That is a new test file, not a change to the legacy file. Run them and keep the results. A failing new test means you misunderstood the current behaviour, so fix the test, not the production code.
  3. Change the one file in small steps. Extract a method around the part you need. Run the characterization tests after each extract. Stop when the new method is the piece you had to change. Leave the rest of the function alone.
  4. If you cannot call the function from a test (it needs a storyboard, a singleton, the whole view controller), sprout the new behaviour beside it: a new function in the same file, tested on its own, called from the old function in one line. The old body stays. That is the move when the constraint is "this file only" and there is no seam.
  5. Get approval before a wider refactor. A minimal extract is the change. Renaming the whole function, or moving it to a new type, is a separate ask.
@Test(arguments: [
    ("PLN", 1000, "10,00 zł"),
    ("PLN", 0, "0,00 zł")
])
func formatsBalanceAsToday(_ code: String, _ cents: Int, _ expected: String) {
    // pins current output, including a format you might not choose yourself
    #expect(formatBalance(code, cents) == expected)
}

If you stall: "How would you know you didn't break anything?" The characterization tests, re-run after every extract.
